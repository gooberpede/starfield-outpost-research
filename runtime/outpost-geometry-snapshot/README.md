# SOR Outpost Geometry Snapshot 0.1.0

Offline research candidate — NOT AUTHORIZED for live execution in this task.
This workflow status adds no condition to GPL-3.0-or-later rights. The unchanged
approved SFSE PluginAPI.h retains its separate MIT notice. No other SFSE source
or runtime implementation is incorporated.

The build reads pinned local game/SFSE files and the installed MSVC/Windows SDK,
snapshots source into a fresh ignored directory, builds the same DLL used by the
owned qualification host and writes a local review ZIP. It launches neither the
game nor SFSE, changes no installation/save/database, downloads nothing and
uploads nothing. Use pinned Python `-E -B build.py <fresh-alphanumeric-label>`.
Optimization/inherited PYTHONOPTIMIZE refuse before output; existing output and
reparse directories refuse. /MD imports installed CRT/STL services; no runtime
DLL, SDK or STL source is separately vendored. Compiler-produced code is present.

A separately approved pilot needs a private DLL-adjacent
`SorOutpostGeometrySnapshot.output-path`: one UTF-8 absolute existing plain local
output directory with final LF. Unicode paths are tested. No installation or
pilot is authorized here. Startup waits for owner absence and actual sole-thread
patch admission, with STOP/STARTUP_STOP in that output directory as its escape.
Observed owned-host helper drain varied around 30–60 seconds; there is no promised
production duration or arbitrary healthy wait deadline. A complete current-thread
OS unwind must exclude all mapped lifecycle/cleanup ancestors; missing metadata
refuses. Startup service exit and one completed registration task gate
COMMAND_READY. Do not use a console/script, load a save or construct an outpost
before that receipt. SORSnapshot explicitly replaces GameComment, preserving
BetaComment. The DLL stays resident; no hot unpatch/unload is offered.

There are eleven installed sites, 59 replaced native bytes and 44 KiB relay pages:
five lifecycle phases, whole area consumer and its callback, whole placement
operation, one pre-release reference CALL and two pre-free source CALLs. No production point-query detour, generator,
visited-key, scheduler, request or lock-admission hook is installed. These guards
and bridges still have residual execution/cache/scheduling effects while unarmed;
they are instrumentation, not non-invasive observation. Legacy point-only scopes

SORSnapshot waits for a naturally occurring established zero-state outpost
placement initialization and its exact area consumer in the same invocation and
accepted-command generation. Background point/area and preview calls do not
consume the arm. The original resolver's successful pre-release path supplies an
additional established-operation witness. Ordinary setup can reach this path;
every Build Mode reopen is NOT guaranteed or live-tested. If it is not observed,
the request remains armed until a qualifying operation or STOP. No forced query,
generation, refresh or automatic retry follows. A completed eligible consumer
without a callback emits NO_FRESH_RESIDENT_CALLBACK; a completed eligible
operation without a consumer emits a scoped refusal. Neither proves absence.

Every represented header and ordered point is owned before independent file IO.
Geometry requires a complete gate-protected current manager binding whose
attached ProcGen equals the native callback operand, plus unchanged preselection
epoch. Missing/wrong binding refuses BEFORE holder/P/map reads. Healthy current-P
geometry remains raw if only source-ending history or identity is unavailable. Reference
FormID/type are copied only during the original resolved-reference lease, before
its existing release. The later pointer-value link does not extend that lease:
post-release allocation continuity, player ownership and physical area remain
UNKNOWN. No reference/base/cell or indexed-vector traversal occurs after release.
The native caller's 24-byte indexed input and module-owned table headers are diagnostics.
Normal publication follows consumer completion; original exceptions propagate
and produce only an owned failure tombstone with native reader release UNKNOWN.
Structural/lifetime/protection failures disable the observer. Healthy identity
uncertainty preserves available raw geometry.

The qualification export rejects every host except its exact SHA-pinned owned

Source history requires a fresh process using the official SFSEPreload path before
ordinary source history; a null singleton or complete current stack alone cannot
establish that prehistory. No hot load is supported. Both original pre-free CALLs
mark their existing RCX address under exclusive observer protection and release
it before forwarding native free. No source is dereferenced in the mark path.
The entire 14-read geography/token/origin/descriptor group uses the shared gate,
fixed owned storage and checked RPM only, with no engine call, allocation or IO.
No gate is held across geometry allocation, native continuation or publication.
C++ and SEH cleanup release it; original SEH propagates. Production checked RPM
is nonalertable and makes no reentrant engine call; unexpected reentry permanently
disables source diagnostics. Source-recording loss is source-only, preserving
healthy owned geometry. SOURCE_LIFETIME_RETIRED and SOURCE_RECORDER_UNAVAILABLE
carry null values in all three source groups.

Address tombstones never clear, even for equal-byte reuse. The process-lifetime
ordered set allocates observer-owned nodes while unarmed and grows until process
exit or allocation failure; exhaustion disables source qualification without
eviction. These allocations, synchronization and pre-free latency are residual
instrumentation effects. The recorder object intentionally has no static
teardown destructor while hooks remain resident. A group completed before a
later ending retains its owned bytes, with protection scoped to that read only;
it makes no subsequent source-lifetime claim. No retail run is authorized here.

The lifecycle repair adds no patch sites. Before any holder-slot, manager/body,
map, geometry or source read, the actual callback must TRY-acquire the observer
lifecycle shared gate and observe zero active native phases. Contention refuses
with LIFECYCLE_COPY_NOT_ADMITTED and zero borrowed reads; it never waits while
holding the native ProcGen reader. The complete owned copy and final binding
checks stay inside that shared scope and a generation-checked read lease.
Missing, released or stale leases refuse before reading.

Every relevant whole owner/ProcGen phase first uses exclusive admission to wait
for existing copies and publish its active count/epoch, then RELEASES the mutex
before original native code. Nested phases count under their admitted outer
phase; no observer mutex is held across an engine lock or native original.
Completion advances epoch before dropping active count. Thus existing phases
make copying refuse, and new phases cannot mutate during an admitted copy,
without serializing mutators that enter engine locks in different orders.
Gate order is lifecycle then source; source marking releases before native free
and never acquires lifecycle protection while holding its own source gate.

Both scopes release on SEH/C++ cleanup; original exceptions propagate. Capture
ownership is established before any borrowed read, so exceptional copying emits
only a failure tombstone instead of stranding the worker. Unsupported same-thread
shared-copy-to-phase reentry raises a private protection exception BEFORE original
mutation. This can abort native control flow: it is a disclosed failure boundary,
not ordinary read-only success. It permanently disables future copying. Subsequent
ordinary phases quiesce prior copies and forward originals inertly without new
injected exceptions or unmatched counter decrements. No fail-fast or engine
termination is used. This behavior still requires independent final review and
separate live authorization.

The actual whole-area entry samples epoch before original manager/P selection
at preferred VAs `0x1421e09d4` and `0x1421e09db`, native reader admission at
`0x1421e09ed` and callback at `0x1421e0a46`.
A replacement after entry therefore changes epoch before any borrowed callback
read. Equal P address is not an allocation token: owned modes56/57 actually
VirtualFree/reallocate P at the same address and preserve all bytes; replacement
after entry refuses with zero borrowed reads, while replacement before entry can
capture the new current P without claiming historical continuity. Missing and
mismatched current binding also refuse before inaccessible P/holder reads.

The supported copy contract permits ordinary non-engine, nonalertable checked RPM,
fixed OS helpers and stock CRT allocations only. An approved effective load set
must not install engine-reentrant allocator/new-handler behavior. Same-thread
reentry reaches the disclosed private protection exception; cross-thread allocator
callbacks that dispatch native phases and wait could create an unsupported wait
cycle. No arbitrary allocator safety is claimed, and no allocator/CRT setter hook
or target-state change is introduced. No concrete violating pinned stock-runtime
handler was identified by this investigation. This scoped limitation must remain
in any future pilot approval and independent safety review.
