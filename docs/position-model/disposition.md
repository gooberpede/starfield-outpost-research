# Application disposition and bounded backlog

2026-10-13. [Specification](specification.md), [capabilities](capabilities.md),
[application audit](applications.md). This is a recommendation for review;
no production importer, integration implementation, deployment or new experiment.

## Usable now

Consume scoped ordinary-beacon positive indicators, typed body associations,
sample-qualified identity and stored transforms. Preserve names as labels and
Workshop IDs as corroboration; report ambiguous joins explicitly. The compensated
local center is a useful durable representation in the demonstrated Save25/26
frame and controlled relocation. Current Tracker body/outpost records, resource
lists and cargo graph require no universal native XYZ. Stored Z can be retained
without promising it is altitude or identical at every runtime boundary.

## Conditionally usable

Use v2 as the research integration contract, with extracted evidence envelope,
supported build/domain, frame, native versus packed domain, required upstream
site cell, per-stage UNKNOWN and confidence/coverage labels exposed. A consumer
may display associated angular **site anchors** or local geometry with provenance
and caveats; it must not infer exact beacon geography, biome, ore or ownership.
Promote the **documented constrained interface for downstream design now**, subject
to maintainer review and the charter's publication/consumption sequence. Do not
label it a production-ready parser or implement the downstream adapter here.
Keep v1 compatibility for historical fixtures, route new scoped calculations
through v2. No algorithm/interface changes were needed in this consolidation.

## Not ready

Exact continuous beacon longitude/latitude, global metre distance, altitude,
universal native XYZ, authoritative object membership, deposits/build eligibility,
effective live boundaries and in-game placement commands are not ready. Each
requires its own evidence; positioning does not solve the other subsystems.
No identified current Tracker or stated network Planner workflow is demonstrably
blocked specifically by unresolved Z or exact continuous geography.

## Deferred questions and reopen contract

The following are prospective experiment designs, not authority to execute.
Reopen only with a concrete agreed feature need **and** the listed falsifiable
measurement, independently qualified identity/frame and competing predictions.
More native samples at the same boundary alone do not qualify.

| Deferred item | Feature trigger and prospective discriminating experiment |
|---|---|
| Runtime XYZ frame reconciliation | An agreed feature converts runtime geometry to saved coordinates. Capture same identity/lifetime and same caller under matched trigger, with independent selected descriptor/index/frame translation and complete before/after XYZ. Predict measured transform equality versus unexplained state change; a nonzero residual falsifies the proposed transform. |
| Z restoration/history | An agreed height-sensitive placement/proximity feature needs post-load Z. Capture one protected-copy load and specific candidate writer, setter operands/output, independent load identity and selected 3D edge/epoch. Competing raw-load versus conversion/replacement predictions must differ numerically; observe the decisive store and consumer or retain unresolved history. |
| Continuous exact lon/lat | An agreed exact map/site finder/global-distance feature requires subcell points. Use independently identified world/site and known geographic reference plus measured local residual across controlled nonzero moves. Center/corner phase and other candidate embeddings predict distinct continuous angles; compare independent native geographic consumer output, including held-out seam/site cases. Round trips of the same model are insufficient. |
| Generic ship marker provenance | An agreed landing-site linkage feature needs marker-to-outpost association. Measure independently resolved request/source world and marker identity across creation/existing-reference branches. Competing shared-source versus distinct-source predictions must be compared against actual selected world/identity and ordinary Workshop evidence separately. |

Prioritize practical research: (1) authoritative saved object-to-Workshop membership
and deletion/reload remapping, with controlled creation/removal and independent
engine/manual association; (2) extractor/resource definition association to
actual deposits and active production; (3) power dependencies and production
state/rates; (4) cargo endpoints/direction/transfer semantics. Existing
[extractor association](../experiments/extractor-resource-association.md) is useful
but does not establish membership/availability. Network/topology work can proceed
with explicit unresolved links. Select one bounded question and separate brief;
do not wait for complete geometry to begin these more relevant domains.
