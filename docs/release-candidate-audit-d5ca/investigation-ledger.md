## Reproduce the audit

From the repository root, use the project Python version and `-E -B`
for tracked verifier entry points. For example:

- `research/archival/archive.py verify docs/audits audits --extract NEW_DIRECTORY` and the corresponding `docs/implementation-briefs implementation-briefs` command.
- `research/archival/verify_navigation.py`, `research/archival/verify_assets.py` and `research/evidence-data/documentation-synthesis-d5by/verify.py`.
- The D5BG and D5BV `verify.py --negative-controls` commands in the [current source crosswalk](../../research/evidence-data/README.md).
- `research/function-catalogue/verify.py` at the proposed full ancestry.

The ignored `.local-work/d5ca/` directory contains the census and byte-review
scripts, intermediate outputs, extracted documentation and no copies of the
nine protected distributions. `surface.py` uses the complete object-store
type/size census. `surface-fast.py` checks an independently enumerated pack
index and loose-object denominator. `evidence.py` regenerates the claim/asset
tables from current and historical ledgers and the approved local files.
`closure-checks.py` compares extracted bytes, historic Git identities and
case-sensitive current links. `hosted-inventory.py` uses the existing
non-interactive GitHub authentication in memory and returns only inventory
metadata. Read-only network scope was limited to the identified repository.
None of the ignored audit tools is a public method dependency.

The 17 mechanical diagrams are in `crew-and-robots`, `identity` and `position`
under guides, and `cargo`, `construction`, `fabrication`,
`inorganic-production`, `locations-ui`, `nominal-biomes`, `organic-production`,
`power`, `resource-generation` (three), `shared-storage`,
`storage-and-output-links` and `stored-resources` under reference.
Actual rendering and independent retrieval of release assets belong to B6.
The scoped external links, including GNU and SPDX licence references,
were inventoried without online validation.
