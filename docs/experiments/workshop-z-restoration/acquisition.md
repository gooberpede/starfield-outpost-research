Any future proposal should first pin the build, exact protected input saves and
observer source/package, and specify a finite gameplay question such as one
load/local-control/new-landing/return sequence, with optional relocation comparison
separately agreed. These are proposed inputs/actions, not permission to run them.
Observe old/new pointers only within one lifetime; reacquire after load, never
dereference stale pointers. Identity must include ordinary base, body and stable
Workshop ID, parent/current-source/key domains, caller sequence and queue ancestry.

The highest-value **same invocation** group is `(reference identity, old flag,
target flag, signed translation XYZ, before XYZ, after XYZ)`. For an edge explanation,
its selected owning source/destination/key/validity/height and the caller that
supplies the vector must be bound to that conversion, not sampled opportunistically
at the later center. The center invocation separately requires reference XYZ,
concrete ExtraWorkshop compensation/ID, actual output XYZ and loaded own-parent.

A new instrument would alter execution/timing and must disclose that effect.
No byte/register/gameplay patching, exception suppression, save overwrites or
debugger revival is proposed. A separate live brief must specify allowed hooks,
bounded memory/queue reads, output flushing, failure/STOP behavior, both-drive
40,000,000,000-byte guards, evidence integrity and recovery/exit policy. Healthy
scientific work has no arbitrary elapsed-time or event-count cutoff. Complete
persisted evidence, scientific equivalence and process survival are independent
outcomes. Cleanup would retire the instrument, verify removal and protected
hashes, and await review; no automatic retry, extra travel or source-save changes.
