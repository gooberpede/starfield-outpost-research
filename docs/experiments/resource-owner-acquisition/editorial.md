# D4D editorial compliance

The complete changed authored set receives automatic screening and actual manual
reading before independent exact-snapshot review. The final package's
`changed-files.json` is the exact byte/hash inventory; the supplied brief is
separately identified and retained unchanged. The screen covers Markdown/CSV and
Python comments/docstrings; C++/header/include and assembly explanatory text was
read manually because it is outside that screen's language coverage.

Manual coverage includes all paragraphs, tables and commands in this directory;
every changed navigation, permission, source and credit paragraph; CSV headers,
origin/use labels and classifications; and all comments/docstrings in
`research/resource-owner-acquisition/`. Existing inherited code comments retain
their provenance and were included in this reading. Opaque hashes, source paths,
native symbols and literal instruction/identifier fields receive identity checks,
not stylistic rewriting.

The manual pass corrected a stale comparator docstring that described discarded
model contradictions, a duplicated relative receipt prefix and a CRLF-authored
audit helper. The latter normalization invalidated an old source-pin check before
its terminal suite could execute; that refusal remains a failed historical
attempt, followed by a new build and full qualification. An initial ledger-write
attempt used the Windows default text codec and failed while reading existing
UTF-8 navigation; no navigation update from that attempt was applied. Explicit
UTF-8 handling and exact-byte/newline checks replaced it.

Notation distinguishes preferred static VA, RVA, runtime VA, frame-relative byte
offset, native FormID word, synthetic test key, geographic cell and observer token.
Source correspondence, Workshop consumption and historical generation epoch remain
separate throughout. Both Water operands remain ordinary numeric loop operands;
no atmospheric pair, two-vein claim or geometry-based deduplication is introduced.
No editorial rule exemption is used. A zero-diagnostic screen does not replace
manual or independent review.

Independent review also found a scientific-readiness defect in wrapper module
resolution. Its reproduced false cached-only STOP and subsequent exact-path
import correction are retained separately from prose-format checks. The new
wrapper test's comments/docstring and the corresponding report/card corrections
are included in the final manual and independent reading.

Independent disposition is bound to the exact manifest and retained verbatim
in the local review return. Substantive post-review edits require delta review.
No screen, manual pass or reviewer decision authorizes integration, retail
execution, publication, staging, commit or push.
