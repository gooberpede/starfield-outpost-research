## Placement and registration use distinct resource operations

The actual placement gate `0x140f3f9a0`, call `0x140f3fd5f`, invokes
`0x140f7c290` on the natural-extractor branch after its bypass-property tests.
The latter obtains ordinary point-admitted resources through `0x14079df70`,
obtains candidate effective produced resources through `0x1409e8700`, then
intersects the two sorted pointer vectors. Empty intersection sets placement
status `0x17`; further construction gates still apply. The native point scan
reads retained collections rather than invoking resource generation. This is
the [qualified D5V consumer contract](d5v-lifecycle-consumer-map.md#native-geometry--area-catalogue-and-extractor-decisions),
not a production test or whole-outpost availability measurement.

Construction registration `0x1421dd600 → 0x140f7c510` and selection registration
`0x141583410 → 0x140f83b90` instead call the effective-property resource
enumerator `0x1409e9150`. They register the Workshop via `0x140f7ee40`, find or
create a resource-keyed array under ExtraWorkshop `+0x20`, and append a producer
row when the existing-handle search does not find the producer. The row stores
current reference handle, base FormID, zero pending, rounded registration
quantity, zero timers and current reason-zero eligibility. Registration failures
or empty enumeration do not promise a usable row.

The registration and placement enumerators are deliberately separate evidence
edges. Registration's callback table `0x144b6efe8` resolves to
`0x1409ea440` at slot `+0x08`, independently checked from installed PE bytes.
That callback tests property class 9 and disabled-property flag, then invokes
`0x1409e9360`. Placement's callback invokes `0x1409e8950`. A shared AVIF/IRES
relationship does not justify treating those two implementations as identical.

Fresh `0x1409e9360` closes that registration edge: it checks three supplied
property-list views for an exact AVIF entry, otherwise calls the reference's
effective value getter at interface `+0x70`, virtual byte slot `+0x18`, and
requires a positive value. A qualifying class-9 AVIF must have a nonnull
resource pointer at `+0x148` before append. Placement's `0x1409e8950` instead
has its own supplied-list/default/keyword and getter tests. Neither enumerator
stores a region or point identity as the producer association.

## What is serialized and reconstructed

| Channel | Actual native writer/reader | Authority and adverse case |
|---|---|---|
| Placed reference and base | EXP0029's supported dynamic inline case-5 REFR representation; installed CONT resource-property bridge | Saved base/resource association survives as identity information. Its original initial XYZ is not automatically the current loaded position or generation frame. Unsupported representations and installed-versus-historical overrides retain their qualifications. |
| Resource map key | `0x140f50660 → 0x140f515a0`; `0x140f50880` | Writer serializes the BGSResource FormID. Reader resolves/remaps and dynamic-casts it to BGSResource; an unresolved/null resource does not publish that loaded map entry. No source pointer, visited token, contour or point-array identity is in this key. |
| Producer identity | Same row writer/reader, including `0x1402cedd0`/`0x1402cef80` and current handle resolution | Saved reference identity is rebuilt as a current handle. Loader initializes the invalid sentinel and retains it if resolution fails. Base FormID is read separately. Equal numeric pointer/handle values across loads are not continuity proof. |
| Producer bookkeeping | Same row writer/reader | Wire body is pending i32, registration-iteration i32, cached eligibility u8, remaining binary32, interval binary32: 17 bytes. Runtime row stride is `0x1c`, with eligibility at `+0x18` after the two floats at `+0x10/+0x14`. The wire order is not a runtime memcpy. |
| Registered Workshops | Global `0x140f7e6f0`/`0x140f7ea10` | Writer saves registered reference identities separately from the directed transfer graph. Loader clears the current handle set and resolves/reinserts current handles, then rebuilds graph/cache state. A registered identity alone does not guarantee successful Workshop/ExtraBC resolution at update. |
| Current operating state | `0x140f7d120`, called by registration, object-load event and due-cycle update | Cached eligibility is historical state. Current power/halt/flags, destination capacity and other applicable gates are re-evaluated before production; a saved true byte cannot certify output after load. |

The positive map loader is sufficient to explain a persistent producer resource
route. It is not a saved-vein loader, nor proof that it runs at a particular
relative instant in an unrecorded B1/B2 transition. Broad ProcGen reset and the
Workshop/global production reset are separate operations on separate receivers.
No generation-map lifetime guarantee is inferred from the Workshop save channel.

## Unload, return and production

Typed `TESObjectLoadedEvent` ancestry and observer registration are established
in the [S2 lifecycle account](../local-output-links/lifecycle.md). Its actual
sink is `0x140f7dfa0`. Fresh exports verify that this sink resolves the event
reference and Workshop, evaluates current production reason, and distinguishes
the event's false and true states.

On false object-loaded state, matching rows have pending bookkeeping cleared
and eligibility updated; this is not UI deletion or source-map retirement.
On true state, `0x140f8c580` matches the current producer handle, updates cached
eligibility, sends a nonzero pending count to `0x140f7d6a0` only if eligible,
then clears pending either way. A missing row permits new registration; a stale
sentinel row is not a proved recoverable debt. These native conditions explain
both continuity and failure cases without asserting that every distant object
remains resolvable.

Periodic `0x140f7ef20 → 0x140f7f1e0` iterates registered Workshops and their
resource-keyed producer arrays. A due row resolves its current reference and
rechecks `0x140f7d120` in mode 1. Reason zero reaches `0x140f7d6a0` with the
**map's resource key**, not a newly selected deposit. That routine resolves
resource `+0x108` recipe and recipe `+0x88` product, chooses an eligible receiver
through `0x140f7d510`, and reaches actual inventory insertion. Ordinary output
may be created at a connected destination, so the machine's own inventory alone
is an incomplete output oracle.

The reason evaluator tests production categories, flags, halt state, linked
capacity, current properties, power and applicable input availability. Its
ordinary harvester category is `0x140f7c9f0`; generic `0x140f7d030` is a distinct
fueled-generator/cargo predicate, not the placement point query. Capacity helper
`0x140f7c210` compares effective capacity with current weight. Neither the
qualified ordinary update nor the restored-row path calls `0x140f7c290` or
`0x14079df70` to reselect its resource. This is a bounded native-path result,
not a guarantee that arbitrary effective overrides, scripts or conditions cannot
introduce additional behavior.

Consequently, a registered, resolved, eligible ordinary extractor can use its
established resource association even when no current point recheck has certified
the deposit underneath it. Resource geometry can change or disappear under a
different lifetime without the inspected production path automatically replacing
the producer key. Whether that specific combination occurred beneath an actual
outpost is **not observed**. A positive producer result cannot establish equal
geometry; a negative result cannot by itself establish absent veins.

## Question disposition and evidence limits

The supported native mechanism is a separate persisted resource association with
conditional reconstruction and production. The remaining indispensable empirical
edge is a matched complete-geometry transition and independently measured output
for the same actual producer. B1/B2 sampler masks and visits do not provide that
pair. An owned emulation of the row logic would not supply it; no such emulation
is labelled retail evidence, and no native producer was invoked on a synthetic
or retail world here.

Q3 is proposed COMPLETE for its conditional mechanism and its explicit
guaranteed/conditional/retail-required distinctions. It supplies no actual
changed-deposit episode; that empirical dependency remains open for parent CQ
and the full-geometry transition questions. Complete geometry, actual output
and current source ownership must be measured separately.
