## New native boundaries

Addresses are preferred static VAs for Starfield 1.16.244.0, image base
`0x140000000`. Native site identity is copied immediately from the inline CALL
return PC minus five; it is not recovered by later worker stack traversal.

| Native site | Measurement and original semantics |
|---|---|
| `0x1422cc410` | Execute the pending-writer XADD exactly once, copying its actual old packed state. |
| `0x1422cc48f` | Success-only native owner store and MFENCE after ownership CAS; copy the CAS's successful old operand. |
| `0x1422cc3f2` | Execute same-thread recursive ownership increment and preserve its changed ESI operand. |
| `0x1422cc366` | Execute reader-count registration and original exclusive-bit TEST. This is registration, not yet successful shared acquisition. |
| `0x1422cc3c3` | Successful shared-helper return path; replay original saved-RBX load using the correct native stack offset. |
| `0x1402c45c2` | Execute final writer release atomic and TEST, preserving native wake decisions. |
| `0x1402c45e7` | Replay MOV EAX plus recursive release XADD while preserving the separately branched-to RET at `0x1402c45f0`. |
| `0x14079fc85`, `0x14079e027`, `0x1421e0a87` | Actual reader decrements in provider, point and area paths, with distinct copied site identities. |
| `0x1407a51b7`, `0x1407a5386`, `0x1407a547c` | Three additional real owner-lock shared decrements found by the fresh receiver census; the same exact six-byte sequence uses the existing reader-release bridge. |
| `0x140982a5a`, `0x140982a92` | Inline final/recursive writer XADD on the same owner lock, bypassing the release helper; copy/validate incoming ECX delta and owner word, preserve actual old ECX and flags. |
| `0x14079fcb3` | Provider exclusive approach before the original helper and helper-return boundary after it. |

Generic native gates avoid a C++ callback for unmatched lock receivers. They
still execute extra instructions and branch/relay work on unrelated locks.
Matched probes add work around arbitration, including between registration and
CAS and while ownership is held. These facts prohibit a claim of negligible
retail influence from lossless output or an offline passing test.

The first positive provider/reset owner registration publishes the watched
ProcGen `+0x40` lock and samples native owner/state. A nonzero baseline refuses
complete earlier-holder history. A second simultaneously active ProcGen refuses
the single-owner design's completeness; it does not silently retarget. Destructor
retirement clears the watch. Re-registration of an equal address uses a fresh
observer lifetime generation, distinct from a game reset count.

Native bridges snapshot registry generation and odd/even mutation serial before
the displaced operation. Capture retains that original generation. A changed,
odd or incoherent registry produces status `0x8` uncertainty, rather than joining
an old in-flight event to a new lifetime. A delayed Register event need not be
first in callback publication order. Epoch changes and unrelated Grid clears
are still interpreted through the source-scoped D5AJ rules.

## Final admission and guard revision

Candidate16's historical full 150-case pass is retained; it is not the final
proposal. Review found that raw runtime vtable hashes would reject an ASLR image
because the guarded windows contain absolute code pointers. The scheduler now
canonicalizes exactly four proven DIR64 slots per vtable to the preferred image
base before comparing the unchanged PE hash. Production and unconfigured owned
adapter guard domains have different explicit metadata. Six original scheduler
CALL destinations also receive PE-pinned 32-byte preimages; runtime-learned
target bytes are no longer accepted as an initial baseline. Component14 has 65
controls, including canonicalized moved-base positives and altered-target
negatives. The candidate builder independently records the loader relocation
census: all twelve vtable slots are DIR64; the checked code windows and complete
three lock-helper bodies contain no loader relocation.

The initial unmatched-before-atomic gate admitted a concrete race: registration
could publish a zero sampled state after another thread passed the unmatched
gate but before that thread's atomic. Final bridges instead preserve native
state and snapshot registry identity before the operation, then check the native
receiver after its effect. A crossing operation emits its old snapshot with
uncertainty rather than vanishing or borrowing the new lifetime. Unrelated locks
still avoid a C++ capture, but now incur native state preservation and bounded
counter admission. This extra perturbation is part of the proposed instrument.

Native core/bridge admission now spans the operation and capture. Its bounded
saturating counters preserve MAX and roll back a core admission when bridge
admission fails. The identity feature is
`causal_bridge_admission_schema=sor-d5am-causal-bridge/1`; mandatory metrics are
`causal_bridge_active` and sticky `causal_native_counter_faults` (bit 1 overflow,
bit 2 bounded-CAS contention). A healthy terminal requires zero active bridges
and no native fault. Earlier wire-version-1 milestones cannot inherit this
stronger admission qualification merely because their event layout is the same.

The STOP adversary pauses the copied writer helper after its pending atomic but
before any C++ Producer, with native/core active and C++ active zero. STOP must
wait, and the admitted event must still flush after disable. Native adapters
explicitly preserve that admitted prefix; direct post-STOP capture calls and
bridges first admitted after disable remain inert. The actual before-operation
crossing test uses a dormant, owned-host-only callback seam; its pointer remains
zero in retail. It publishes the native watch after the old snapshot and before
the exact original atomic. This is a controlled interleaving, not a retail
timing observation.

Candidate17's STOP assertion failed because its test called the outer exclusive
wrapper, whose legitimate C++ Producer was already active. The revised control
calls the original copied writer helper directly. Candidate18 failed to link an
unused inline fixture callback symbol; explicit select-any storage corrected
that emitted-object issue. Candidate19 passed its six cases but source changed
during the run, so its preservation gate failed. Candidate20 passed its exact
object ABI controls but still dropped a pre-STOP admitted event when capture
resumed after disable; candidate21 adds explicit native-admitted capture. All
these receipts and source snapshots remain local and superseded, not deleted.

The exact candidate21 bridge object passed 2,193 independent assertions and 128

The new checks include watch publication during the actual saved-state bridge
and both native admission counters at MAX. The full candidate regression and

### Candidate23 correction and qualification boundary

Candidate21 later completed all 150 expected case exits, but its source changed
during the run and it has the reviewed pre-admission STOP race. It remains
historical. One direct candidate21 STOP probe also exceeded the combined
ten-second owned terminal-wait assertion, although its persisted healthy terminal
contains the additional admitted event (67 versus 66). Candidate22 split that
assertion, used a sixty-second owned terminal wait, and passed both direct native
and STOP cases; source evolution still invalidates its preservation gate. These
are fixture deadlines, not proposed retail scientific quotas.

The final admission revision rechecks enabled **after** holding the native core
and bridge counters. A thread paused after an earlier enabled check cannot
become an admitted producer after STOP has terminalized: it rolls back both
counters and executes the original operation inertly. Conversely, an admission
accepted before disable retains its event through flush. The owned STOP control
now includes both threads simultaneously: one paused before counter admission,
another paused after its native atomic and before C++ admission. Terminal must
wait for the latter, persist its event, then precede resumption of the former
without a subsequent enqueue. This addresses the independent review's actual
counterexample; the earlier active counter alone did not.

The [fresh owner census](d5am-owner-lock-census.md) found five indispensable
additional inline release sites. Candidate23 includes sixteen causal sites,
six typed reader decrements and two inline writer decrements as well as the
original generic helper probes. Incoming inline ECX delta and pre-atomic owner
word are copied before XADD and validated, preserving the returned old ECX,
original registers and flags. The event retains actual atomic old/new state;
wrong input produces invalid-operand status and a sticky recorder failure.
The separate `d5am-native-operand` case deliberately changes an owned input MOV,
executes the installed original XADD once, and records/refuses the resulting
`0x401000 -> 0x400fff` transition. It restores the test code but does not clear
the failure or reuse the invalid owned lock. The final regression roster is
original 144 plus seven new cases: **151**.
