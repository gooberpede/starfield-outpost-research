## Dependency coverage and limits

The inherited D5AE source graph follows preparation destruction, dependency
commit/completion, rank propagation/rekey and bounded external Reschedule
producers, service pump publication, queue claims, density/layer provider routes,
geographic ingress and reset/removal. Its resolved branches are reused with
source hashes rather than mapped again. No coordinate/mask priority operand is
present in the inspected dispatch/claim/admission predicates. This is a bounded
operand/CFG result; it is not a universal claim that all gameplay has identical
worker service or no timing bias.

Failure controls retain prepopulated aggregate/map, pending request, missing
metadata/raster, failed visited reserve, returned-empty generator, separate
owner/key/token and reset/removal cases. A map holder is inserted before raster
loading and generation, so later post-authority cost cannot choose a new winner.
Holder allocation failure is not claimed safely recoverable. Detached source
retirement can invalidate a raw source despite Grid retention; this invalid
lifetime case is outside a well-defined ordinary successful construction.

The material remaining question is whether C1–C4's **measured ordinary execution**
usually supplies the same effective query class before alternatives obtain the
map. Native feasible alternatives disprove a structural guarantee; they do not
disprove a statistical preference. No offline schedule count assigns probability
to those alternatives. B2 lacks the callback/lock/queue history, and player
observation lacks independent cold-state and complete-population comparisons.
An observation proposal must test these concrete candidates rather than collect
unexplained winners. The [runtime matrix](d5af-runtime-discriminators.md) gives
the minimal missing variables and explicit disproof outcomes.
