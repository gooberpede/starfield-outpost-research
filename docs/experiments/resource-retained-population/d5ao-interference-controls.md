# D5AO interference controls

2026-11-04, Australia/Sydney. Parent D5AO-Q3, GC-10/D5R OPEN.
This record separates controlled native-fixture results from later retail
evidence. Final numerical outcomes and exact receipts are recorded below.

## Experiment contract and method

The question is whether a counter collision can change which contender first
acquires the real native non-ticket writer lock. The positive hypothesis is
that 0.9.2's failed-CAS Sleep can let a slightly later contender pass. Contrary
controls use a separated contender and a collision path without voluntary
descheduling. Passing counter accounting alone is not the oracle.

Authorized inputs are the pinned installed PE, retained build16 sources,
maintainer-owned counter/observer/reader methods and pinned local MSVC/MASM and
Python. Actions compile and run disposable owned hosts only. Outputs are fresh
ignored build/session/qualification files under `.local-work/d5ao/`; originals
are read-only. There is no game, deployment, debugger, database open, protected
save/configuration write, external dependency or network action.

Risks are owned-host crash/hang, disk consumption and fixture errors. Both
drive floors remain 40,000,000,000 caller-available bytes at inherited build,
case, package and operational checkpoints. Real identity/guard/accounting faults
refuse qualification. Preserve failures and diagnostics. A finite test workload
or owned synchronization failure is not a new retail time/event cutoff.
Cleanup releases owned pages, handles and threads and leaves all evidence in
place; no original, historical artifact or active game process is removed.

The new [native sensitivity fixture](../../../runtime/construction-winner/d5ao_sensitivity_fixture.inc)
is included in the actual integrated observer build. It executes the same
shared-target hook/geometry composition as the inherited native suite. A separate
unhooked reference page copies the exact original reader/exclusive/release
instructions and relocates only their authenticated import slots. The hooked
path uses those same shared native helper pages with the actual causal bridges.
For sensitivity only, default-off private wait/wake substitutions use real
WaitOnAddress and WakeByAddressAll instead of a simulated foreign release.
The broader inherited regression keeps its original controlled substitutions.
The typed private reader-release stub omits the retail conditional-wake
continuation, so the sensitivity control explicitly performs WakeByAddressAll
after that decrement. The original omission produced a retained development
deadlock; it is neither a production lock defect nor a passed control.

Each envelope runs twelve off/on pairs for both 250 microsecond and 20 millisecond
contender offsets. A private pre-CAS callback lets a real rival increment the
same atomic object between A's load and CAS. The rival acknowledges this change,
then waits the declared offset before attempting the native writer. A resumes
and executes the tested counter path before its native attempt. Both acquire
and release the same lock; the first owner records the winner. Off controls use
the same event handshake without A's counter admission and execute unhooked native
instructions. The resulting difference includes counter and hook cost, not a
mathematical isolation of Sleep from all other work.

Three rebuilt integrated envelopes compare the historical bounded increment
algorithm, the exact 0.9.2 helper and the proposed 0.9.3 helper. The bounded
comparator retains modern checked teardown and diagnostics: it is an algorithm
comparator, not the untouched historical 0.9.1 DLL. Its separate 32-plus-interferer
refusal control remains the existing source-preserved D5AN test. The qualifier
checks that non-counter fixture/native sources match between envelopes.

The decisive oracle requires a witnessed off-A/on-B close-race reversal in the
sleep envelope, a close-race off-A/on-A control in the new envelope, and an
off-A/on-A separated control in each. It retains all other outcomes rather than
requiring a chosen winner in every repetition. The [qualifier](../../../research/resource-retained-population/d5ao_sensitivity_qualify.py)
also authenticates actual emitted counter/causal/scheduler frames and healthy
terminals. A complete record with an induced reversal is a successful detection
of bias, not permission to claim an unchanged uninstrumented winner.

## Timing, retries and uncertainty

QPC brackets one controlled collision interval per observed race. That interval
includes the shared event handshake and OS scheduling; it is not a pure helper
latency or a measurement of thread suspension alone. One rival increment between
the saved value and CAS guarantees at least one failed comparison. The recorded
forced-collision count is an input/witness, not a full retry distribution.
Source and actual compiled control flow identify the Sleep request on 0.9.2's
failed comparison. Requested Sleep(1) has no one-millisecond upper bound.
No OS context-switch trace or ordinary retail suspension frequency is invented.

The reader/writer control requires a positive wait-branch invocation and pending
writer bits before releasing its reader. A pre-call thread flag or elapsed delay
alone is not accepted as contention evidence. Callback context is atomic because
the real worker may have loaded the global callback while main disables it.

Per-counter-ID uncontended next/leave timings bracket batches of 4,096 operations
on the common noinline helper. The same helper implementation serves all repaired
call sites; ID affects only the fault path, not the successful update. These
samples measure the shared primitive, rather than distinct inlined caller costs.
Twenty repeated sixteen-operation batches additionally bracket actual C++
scheduler/causal Producer lifetimes and native reader/release and
writer/recursive/release paths with their assembly bridges. Native operations
contain multiple sites; no unsupported individual bridge duration is inferred.
Other actual sites retain source/ABI/integrity coverage in the census and suite.

QPC overhead, event synchronization, thread creation, timer resolution, compiler
layout, worker draining, cache state and concurrent test-host load affect elapsed
values. Finite controlled offsets are discriminators, not an estimated retail
delay distribution. No percentage CPU threshold substitutes for reversal
discrimination. No test certifies zero perturbation or universal starvation
freedom.

The integrated regression also exercises 2/4/8/16 simultaneous producer threads,
recursive and nested producers, original-instruction shared users, task dispatch,
identity ABA, registry/token/queue adverse cases, source mismatches, lost records,
partial admission, overflow/underflow, startup and STOP/drain races. Its exact
final receipts and limits belong in the final report, not in a generic pass count.

## Exact-final observations

The actual qualifier at
`.local-work/d5ao/sensitivity-final01.json` passes against final05 and the
historical-bounded03/historical-sleep03 envelopes. Every envelope authenticates
4,092 causal frames and one scheduler frame, including matched owner,
pending/acquired, reader/release and recursive/release events. Each positively
witnesses one native wait-branch invocation and pending writer bits `0x1000` in
the reader/writer control. No counter fault, drop or unhealthy terminal is accepted.

| Envelope | Close off-A/on-B reversals, 250 microseconds | Separated reversals, 20 milliseconds | Close observed interval, minimum / median / maximum, microseconds |
| --- | --- | --- | --- |
| Historical bounded increment algorithm | 0 of 12 pairs | 0 of 12 pairs | 24.9 / 40.3 / 89.5 |
| Exact 0.9.2 sleep helper | 12 of 12 pairs | 0 of 12 pairs | 8,634.1 / 14,815.3 / 15,512.2 |
| Proposed 0.9.3 helper | 0 of 12 pairs | 0 of 12 pairs | 26.6 / 63.75 / 148.8 |

Every reference pair has A first. The separated controls keep A first in both
off/on halves. This is a positive induced lock-admission reversal and a contrary
control, rather than a throughput threshold. A stable empty source map protected
by this lock can therefore have its first entrant changed; no actual retail
construction or its frequency is measured here.

QPC frequency is 10,000,000 Hz. Across the nineteen ID batches, next averages
range from 8.94–9.25 nanoseconds for the new helper, 8.98–10.40 nanoseconds for
the sleep helper's uncontended path and 12.94–13.77 nanoseconds for the bounded
comparator. These are batch averages, not single-call resolution or a fairness
bound. Actual C++/ASM path batches and all raw min/median/max values remain in
the receipt. The absence of a reversal in twelve new-path pairs does not establish
zero observer effect under other schedules.

The independent native helper inspection additionally bounds exported functions
by their PE unwind ranges and resolves actual direct imported calls. Each new
helper has its guarded LOCK CMPXCHG and LastError preservation with no direct
wait import; each 0.9.2 comparator helper has a direct Sleep call. Whole-DLL worker
Sleep imports and source-controlled private indirect callbacks are not confused
with those hot-path instructions. Exact disassembly remains local under
`helper-native-final05/` and `helper-native-sleep03/`.
