**An in-process observer now builds and distinguishes a witnessed region chain
from incomplete, hit-only, bypass and contrary evidence in real disposable
Windows processes.** This is a Phase A engineering result. No Starfield process
was launched or attached, no plugin was installed or removed, and no Vortex,
save or game/configuration content was changed. The selected Feynman V source's
actual construction/reuse and the scientific hypothesis remain untested.
Technical corrections are qualified. On 2026-10-29 the maintainer explicitly
accepted the documented decision-record timing deviation for D5P Phase A only.
Independent dispositions and exact final delivery are governed by the review
record. This acceptance grants no Phase B or deployment authority.

## Implemented evidence path

Five natural CALL wrappers observe source-map lookup, query conversion,
synchronous generation, the actual ordinary mask result and region append/copy.
One branch detour directly observes the saved visited outcome. Five lifetime
wrappers invalidate joins on reset, destruction, erase, Grid clear and standalone
source retirement. This is eleven justified boundaries, not fourteen debugger
traps translated into hooks. No debugger, INT3, DR register, exception suppression,
forced generation or extra native gameplay call is used to acquire observations.

For a qualified invocation, the observer captures original query words,
manager/ProcGen/source identities, source descriptor bytes, effective descriptor,
ordinary mask, exact ordered native point words, bounds and owned wrapper/
resource/collection/index. It verifies the current manager's ProcGen, Grid
membership and relevant native types. A successful append must copy the
temporary region exactly. Completed state is then read through the final owned
map under the provider's still-held native protection. A later map hit must
match that ownership, actual region address and exact geometry in the same
conservative epoch. Failed reads, incomplete frames and intervening lifetime
activity close the affected claim. A failed or changed region is not used as
the witness; a separately complete good region may still qualify with
`population_partial` explicitly attached.

The map key is the full native source pointer; the visited key at source
`+0x68` is separate. Geographic identity, native pointer, observer invocation
and lifetime epoch remain different domains. Reset/retirement entry and exit
advance a global conservative epoch and mark the in-flight hazard. Unrelated
sources may lose joins too. This prevents demonstrated pointer/allocator ABA
joins without claiming an exhaustive engine-wide alias/writer census. First
observed construction is never first-ever construction.

The hot path uses bounded owned-byte copies and a reusable MPSC ring. The
worker writes append-only sequence/CRC frames, flushes raw bytes, then flushes
identity-bound cumulative acknowledgments. The independent Python reader checks
approved DLL identity, session identity, framing, CRC, sequence and acknowledged
prefixes before reducing evidence. Terminal identity is checked separately.
Owner and raw mode must match across demand and reuse; actual generation owner
and converter descriptor must agree with the construction context. Original
temporary geometry and its copied destination are independently recorded.
Enqueued, written, flushed and independently verified are not interchangeable.
A post-flush crash can preserve a useful decisive prefix; a pre-flush crash
does not. Raw masks, including unexpected values, are preserved without fitting
them to historical geometry.

The final reader authenticates 4,517 acknowledged native records. Continuous
production with an active worker wraps the queue and retires cleanly after
3,132 records; a simultaneous STOP/request receives no fresh readiness ACK.
Owner-only, mode-only and effective-descriptor changes block reuse joins.
An actual good copied region remains a qualified witness when another append
fails, with `population_partial` explicitly attached. Construction-only,
retention-only, hit-only and contrary counts remain separate.

These are original executable Windows fixtures, not JSON-only reducer examples.
They use the same DLL hooks and recorder, with a fixture entry that refuses a
retail host name. Fixture models supply native-shaped objects and controlled
events; they do not emulate the whole engine or prove that Save52 will reach a
successful selected-source construction. The production SFSE loader path,
sole-thread availability, real scheduling and throughput remain NOT TESTED.
The READY card enforces that boundary before any experimental save load.

General asynchronous unwinding through the inline branch and emitted prologue
trampolines is unsupported. The ordinary capture callback is nonthrowing; a
separate generation-exception fixture checks ordinary C++ hook-scope cleanup.
No universal exception recovery, retail crash prevention, safe mod integration,
complete resource census, consumer linkage or persistence finding is claimed.
The engineering bounds are 64 points and 256 slots/members/regions per relevant
traversal, with 1,024 reusable queued events. Exceeding them is incomplete
coverage, not an absence result or an arbitrary scientific session quota.

## Preserved failures and corrections

Early builds exposed MASM label scope, an assembly/C++ object-name collision,
and loader-worker sole-thread refusal. Later work corrected atomic counter
assignment, stale MPSC producer handling, inactive-wrapper sampling, terminal
identity, guard/ACK ordering and missing invalid-invocation handling in the
reader. Build10's reader raised `KeyError: 0` on an incomplete-read event; that
run was not accepted. The corrected reader leaves it unqualified instead.
Build09's evolving test inventory and transitional source-drift failures are
retained as failed development runs, not green qualification. Build08's smaller
green envelope is preserved but is not the deployment candidate.

Independent review01 required current owner/mode and actual descriptor checks,
bounded drain/flush batches, closed-session READY checks and explicit output
categories. Build13's first continuous-production control exposed real overflow:
1,079 records were flushed, one drop was reported and instrumentation failed.
That failure remains preserved. Build14 uses buffered stream writes with the
same explicit raw-flush then ACK-flush durability barriers, snapshot-bounded
batches and a declared paced continuous fixture. It does not claim the previous
aggressive rate passed, nor establish retail throughput. The crash-before/after
flush controls were rerun on the exact final DLL.

The comparison decision was made during initial source investigation; its
durable design record was written after the initial prototype, before final
qualification. This is a sequencing deviation from the requested pre-coding
record, disclosed for independent and maintainer review. AC1–AC8 themselves
were not weakened or substituted. No native/game failure is hidden by these
engineering corrections and no old D5L–D5O verdict is changed.
