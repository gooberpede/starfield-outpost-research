## Minimum future capability, recommendation only

An observer should preserve identity at the **pre-map visited boundary** without
following an unqualified selected pointer. One candidate is a constructor/writer
witness that records the engine's already-consumed identity operands while the
new source has an established allocation lifetime, then correlates an allocation
cookie through publication and retirement. A visited witness could record the
token and other operands the engine itself has consumed. This needs a verified
writer/owner lifetime contract, not a retrospective pointer dictionary. The
detached-density lifetime gap in D5S remains a counterexample to assuming source
retention from Grid retention alone. A token must not silently be assumed
collision-free or interchangeable with a geographic source key.

Record the actual reserve return and successful token-store boundary, preserving
failure sentinel `0xffffffff` as a separate outcome. Keep original request,
selected source/allocation, consumed descriptor, actual decision epoch, map
hit/miss, generator/sample and subsequent bypass correlation. Preserve global
reset and firstness/lifecycle events even when non-target paths dominate.
Blindly filtering only inferred target pointers could erase the evidence needed
to qualify firstness and is rejected.

To attribute player-action timing, minimally correlate pending transition
publication/consumption, owner/descriptor installation, focus/region preparation,
task registration/claim and provider invocation with native monotonic ticks and
thread/parent identifiers. Add an independently qualified visual-arrival or
loading-state boundary only if that particular ordering is the new question.
Operator notes and sampled ACK watermarks remain intervals, not native instants.

## Capacity and loss controls

The unchanged event payload is 312 bytes plus an eight-byte queue ticket; the
current `Cell` layout implies 320 bytes per cell at the present alignment.
Estimated static queue payloads are 327,680 bytes (1,024), 2,621,440 bytes
(8,192) and 10,485,760 bytes (32,768), excluding other globals, output buffers,
TLS and allocator/runtime overhead. They are calculations, not measured working
sets or compiled larger-queue layouts.

[capacity-sensitivity.csv](d5aa/capacity-sensitivity.csv) evaluates all three
capacities against admitted B1 QPC samples with serial producers and ideal
periodic snapshot drains. At 1,206.5674 ms spacing the 1,024-cell replay refuses
13,512 admitted inputs; the two larger models refuse zero, with peak occupancy
5,555. These are model outcomes under one phase convention, not recovered losses,
throughput guarantees or qualifications. Lost attempts have no timestamps;
concurrent reservations, CRC/guard work, wake latency, actual flush placement and
changed observer timing are absent. No modified observer is built or tested.

A future candidate needs actual multi-producer capacity/wrap/contention tests,
delayed worker/wake/flush and I/O fault controls, preserved reset/firstness events,
independent damaged/truncated/omitted-boundary refusals and all original identity,
source-lifetime and cold-history controls. Timestamp worker wake/drain/write/
flush operations to distinguish causes rather than attribute a cumulative delay
to one bottleneck. Larger capacity never establishes capture completeness.
Fail scientific firstness qualification on relevant loss until a fresh complete
reset/history boundary; continue safe evidence acquisition under existing policy.

This is a design recommendation. It grants no implementation, dependency reuse,
build, deployment, live launch, debugger, save operation, Git integration or
publication authority. D5R remains OPEN; the narrow next maintainer decision is
whether to pursue a new observed construction episode with these capabilities.
