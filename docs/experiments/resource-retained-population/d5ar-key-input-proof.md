# D5AR packed cells and source BIOM

2026-11-05, Australia/Sydney. REVIEW-REQUIRED. Addresses are preferred static
VAs for the pinned 1.16.244.0 executable; member offsets are not runtime addresses.

**Under the ordinary initialized tree, descriptor and stitching premises, the
actual A0 source reconstructs all 144 ordered C1 cell keys.** This comparison
does not consult the geometry outcome. A separate main-file raster calculation
tests the source BIOM premise without taking that identity from the fixed C1
result or inverting a resource count.

The [clip controls](../../../research/resource-retained-population/d5ar_clip_controls.py)
establish the ordered `[1,13) × [1,13)` loop for reconstructed A0 dimensions and
origin with stitch 2. At `0x14079a3f5`, the per-cell generator calls `0x14078d7b0`
with origin plus the integer cell. That function reads `manager+0x120` and
then Landscape `+0x58`, a linked SFTR pointer. It selects descriptor `+0x1c0`
in mode 3 or `+0xc8` otherwise and calls `0x14096f5c0` on a stack copy. It packs
tree `+0x58/+0x5c` system/body, output chart, Y and X. The normalized placement
metadata is not used for those packed bits.

Original `0x14096f5c0` computes chart and two coordinates from descriptor
`+0x00`, `+0x04/+0x08`, `+0x14/+0x18`, `+0x24/+0x28`, block-plus-merge and
tree width `+0x50`. The signed native divisions reduce the source-adjusted
offsets. The 144 cells stay inside chart 0, so the seam branches do not change
the chart. Later reads of tile and placement words can update the local copy
at `+0x0c/+0x1c` but leave the packed coordinate lanes unchanged. The prior
original `native-keys03` execution used a null definition resolver; the
non-null typed placement branch likewise writes only those placement lanes.
This explains why its explicit descriptor coordinate fixture may stand in for
this key calculation without certifying identical placement metadata.

The actual A0 source descriptor recovers chart 0 and anchor `(37536,20928)`.
Its source origin is `(-200,-200)`. The unoverridden body PNDT `0x0005e0de` has
GNAM system `86469` and body index `5`; its native link selects SFTR
`0x00168814` with DNAM width `256`. Original `0x140771076` stores the tree into
PNDT `+0x38`; the same path assigns the tree owner and system/body. In the
Landscape module install, `0x140784680` locks the module, selects the manager
body, calls typed PNDT/tree getter `0x14096b8e0`, and writes Landscape `+0x58`
at `0x1407846b4`. The getter reuses the installed linked tree when present; its
missing-tree generation fallback is a different route. Owner installation and
the Density drain/body interval are addressed separately in the
[effective-input gate](d5ar-effective-input-gate.md).

The source BIOM takes a different native path. The provider passes `source+0x10`
to `0x14078ee90` at `0x14079fb16` and retains its non-null result through the
generation call `0x14079ff18`. `0x14078ee90` selects the active manager descriptor,
transforms the source anchor, leases the ready `manager+0xf8` map entry and
calls the row/column function `0x1423390f0`. This reads a BIOM FormID from the
face's identity array, rather than the separate request-dependent mask nibble.
See the [B1 native map and identity chain](../outpost-biomes/native.md).

The [owned archive lookup](../../../research/resource-retained-population/d5ar_biome_input.py)
uses B1 BA2 framing and RG1 map lookup under SOR-P-0002. It rehashes the installed
PlanetData archive against A0's preflight pin, extracts only the bounded main
Feynman member in memory, and cross-checks the map parser result against the
independent integer address and direct little-endian load. The initial control
refused because A0's postflight comparison does not list `installed`; the
corrected control explicitly records that omission rather than claiming the
postflight compared BA2. A second attempt compared the digest to the pin object
and refused; the corrected control compares its actual `sha256` and byte count.
`biome-input03.json` (SHA-256
`c03c55a6efab6843491bec2519186fb09994483283e0883bc2fd3c5fdd601385`)
resolves pixel `[0,195,146]` to `0x00145440`. This agrees with the positive
conditional component calculation for the initialized main definitions. The
new hash comparison authenticates the current
archive bytes against the earlier preflight, not the actual priority of all
possible historical archives and loose files. A0 records a BIOM pointer, not
its FormID or the selected raster identity. Thus the normal main-file route
can establish a positive conditional selection without manufacturing a retail
observation. Neither key nor raster result proves full A0/C1 effective inputs
or future resident capture eligibility.

The authenticated A0 archive contains a successful preflight, 39 definition
pins, 23 configuration pins and three installed anchors, including the main
PlanetData BA2. The recorded Vortex profile and effective DLL checks are
described in the [A0 report](d5ak-a-report.md#qualified-acquisition). Neither
the archive member roster nor those checks enumerate all effective `.biom`
providers or record the opened stream's member and hash. The ordinary native
loader selects by body name and plugin namespace and can fall back after an
invalid load. A present-day loose-file inventory cannot recover that historical
selection. An authenticated resolver/open trace or an immutable historical
provider and priority inventory would address this remaining premise; neither
would by itself certify future settings or component stability.
