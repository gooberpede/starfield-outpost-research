The least supported input at the loaded updater boundary is therefore **state +
indexed center/context + radius + upper scalar**, with native loaded dependencies.
This is a minimum of the mapped operand roles, not proof that every argument
is independently variable or that no higher-level context can supply more of
them. A fresh complete set cannot be promised solely from those values without
the prior cache and initialization conditions. The state is substantive input:
it may contain retained spatial/ATMO/BIOM vectors from earlier calls.

For prospective preview, the native reference supplies position/frame context
while the operation supplies bounds. For established Workshop, the engine has
a descriptor builder that supplies both position and bounds. The static paths
converge at the same updater. Whether identical qualified descriptors and epochs
produce identical displayed sets for both contexts has no independent established
runtime comparison in this corpus. This is an exact coverage gap, not an absent
implementation guessed from a region-array model.

No smaller sufficient loaded contract is established from a body ID, global
latitude/longitude, saved beacon token, current BIOM ID, planet-wide allocation,
IRES identity list or extractor registry. Each loses a demonstrated dependency:
local frame/source selection, generated regions, cache state, or population
selection. This says what the mapped engine uses, not what another system should
implement. Remote/unloaded query feasibility is outside this assignment.

The offline version-2 evaluator deliberately exposes complete qualified regions,
translated XYZ, radius/upper, atmosphere/biome lists, selected-water observation,
enumeration completeness and allocation qualification. Its conditional output
and UNKNOWN behavior are documented in the preserved
[specification](../resource-availability-milestone-b/specification.md).
That reproducibility contract is broader than the native outer argument list
because it replaces hidden context with explicit evidence. It is not a newly
discovered engine API, and passing synthetic examples does not prove native
loaded generation or a particular archived query.
