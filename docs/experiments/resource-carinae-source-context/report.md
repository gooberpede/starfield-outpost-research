## Acquisition and disposition

The next observation is **consumption-time source identity**, not an ambitious
producer-to-consumer epoch reconstruction. At each accepted/rejected terminal,
C2B copies source-map key → 0x70 source bytes and global manager → 0x200 manager
bytes, verifies manager member `+0x130` equals the callback's ProcGen pointer,
and checks the occupied key/wrapper slot before and after copying. It retains
raw descriptor fields and owner key separately from interpretation. Equal
copies certify the stop snapshot only. All historical inputs and epochs remain
null. The same copied bytes can be compatible with different producer histories.

This route can distinguish a source/frame/owner disagreement from agreement at
consumption, even when the source is cached and no producer executes after load.
If all consumption context agrees, it leaves generation selection/history versus
algorithm unresolved; a later, separately scoped producer capture may then be
justified. The proposed card deliberately does not add that architecture now.
