# Outcome decision and minimal discriminating acquisition

2026-10-15. [Original criteria](../../implementation-briefs/CODEX_BRIEF_SOR_inorganic_resource_availability_milestone_B.md),
[native dependency boundaries](native-provenance.md), [coverage](validation.md).

**Outcome B is the supported disposition.** The executable now includes the
native multi-point spatial predicates; it is more than a union. B2 follows
concrete source/component, descriptor, generation, competing-region and index
dependencies. Available 0.7.0 evidence independently validates the last UI fold,
but supplies no qualified region-count/point/width plus callback-result pair.
Outcome A cannot be inferred from exact final-set agreement or 11,128 positions.

Two native models can both explain all captured lists: a broadphase-only model
and the recovered strip/height/edge model, provided unobserved candidate geometry
is chosen accordingly. Likewise, cached results can recur at different positions.
The static native code discriminates the actual algorithm, but the captured
outputs cannot validate the implementation's numeric transcription. Guessing a
vein from an Iron/Alkanes transition would use the output to manufacture its own
input and produce circular validation.

For independent B1 validation, the minimal future evidence is one complete linked
native query enumeration with actual transformed query XYZ, radius/height,
retrieved candidate keys/resources, each candidate's region descriptors and
point arrays **as consumed**, per-region decision and final spatial collection.
Record before/return validity and lifetime, frame table entry and operation
identity. Include rejected candidates: only logging accepted regions cannot
measure false positives or qualify enumeration completeness. Preserve selected
ATMO/BIOM/selector identities and actual UI inputs/rows separately; use command
ancestry only where actually captured. No renderer timestamp is necessary.

The useful discriminating conditions are native count-zero/one versus multi-point
regions; broadphase tangency versus strip rejection; XY interior at different Z;
vertex-height boundary versus 3D-edge acceptance; and repeated cached versus fresh
evaluations. A future brief should use natural attainable conditions and report
unreached branches as NOT TESTED. It must not force or synthesize game operands
to claim independent capture. Synthetic controls already exercise these choices.
An A/B/C Kreet preview sequence can anchor set comparison without an arbitrary
event/time/size cutoff or requiring extractor construction.

For B2, full planet generation is unnecessary to validate B1. Capturing the
qualified region representation is sufficient. A separate arbitrary-site
reconstruction effort would need the selected CTPerBiomeData/source override,
terrain frame/index and actual generation/collision context described by the
ledger. Existing source keys, definitions and RNG first-gate calculations are
useful partial inputs, not proof that those later quantities are recoverable.
Generic saved components have not been proved to omit all equivalent state.

This is a decision-ready evidence requirement, **not a hook implementation or
live run card**. Any future live brief must separately approve exact observation
sites/build/sample, intervention/timing effects, finite question scope, protective
save policy, group-flushed evidence, disk guard and exit/recovery behavior. This
assignment authorizes no launch, hooks, deployment or save writes.
