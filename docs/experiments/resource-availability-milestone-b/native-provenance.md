## Actual candidate traversal and representation

`1421e09d4..1421e0a77` obtains `manager = [145fd9c30]`, `ProcGen = [manager+130]`, locks ProcGen+40, and scans the occupied 24-byte slots in the array at ProcGen+20 with capacity at +28. Slot+10 equal to `ffffffff` denotes an unused slot. For every occupied slot it passes the address of slot+8 to `1421e0f50`. The callback dereferences that pointer and scans another occupied 24-byte map at source+20/+28. Each entry's first dword is resolved through `1405de3b0`; null or non-IRES (form-type byte +2e other than 9f) is skipped. The entry's +8 points to a region collection, with dword count at collection+8 and region data pointer at collection+10.

Each region is 48 bytes: center XYZ at +0/+4/+8, scalar broadphase radius +c, point count +18, point data pointer +20. Each point is 16 bytes: XYZ plus a fourth width scalar. Empty collections do not qualify. The callback inserts the resolved **IRES pointer** into a pointer-keyed set when any region qualifies. Numeric FormID, IRES pointer, candidate source key, saved token and display label are separate identities. A complete B1 region census can use these loaded maps directly; reproducing every planetary terrain cell is unnecessary when the loaded operands are available.

The query position is an indexed native position. If its index dword +c is below the current `1461fae80` count, the callback adds the corresponding 12-byte translation from `1461fae88` separately to XYZ using binary32 additions. Otherwise it uses the stored XYZ directly. An unrelated invocation's translation table cannot qualify this position. A reflected/translated upstream landscape frame is not an instruction to reflect already resolved geometry again. The executable contract takes coordinates after this transformation and requires the caller to supply its provenance.

## Spatial algorithm in execution order

All arithmetic below means separate binary32 instructions, with no implicit FMA. The evaluator qualifies finite normal/zero operands and finite normal/zero intermediate arithmetic under round-to-nearest binary32. Subnormal, nonfinite, overflow and unavailable rounding state remain UNKNOWN; this is deliberately narrower than claiming all x86 exceptional values are implemented.

1. Compute `dy = region.y-query.y`, `dx = region.x-query.x`, and `distance2 = dy*dy+dx*dx`. Compute `sum = region.radius+query.radius`, then `sum*sum`. A strict `distance2 > bound2` rejects. Equality passes. Only XY participates. The raw VCOMISS/JA behavior for NaNs is not replaced by a claimed portable numeric rule: unqualified NaNs yield UNKNOWN in the evaluator.
2. After passing, point count one accepts directly. It does not read that point or test its width, Z, the separate height operand, or a footprint. Point count zero rejects. Missing point bytes do not block these count branches when the independent count is qualified.
3. For count greater than one, process consecutive pairs A,B, from points 0–1 through n−2–n−1. There is no implicit last-to-first path closure. Normalize the full 3D difference B−A; `VDPPS 7f` computes the squared length and `VSQRTPS`/`VDIVPS` the direction, with zero/infinity masks. Repeated points generate a zero direction. The evaluator conservatively rejects arithmetic outside its qualified numeric domain rather than claim all masked exceptional cases.
4. Rotate that direction about Z by the fixed native `-pi/2` operand through `1404a7f90`'s binary32 polynomial sin/cos routine. Do not substitute an exact perpendicular. Then build the four vertices in order `A-widthA*v`, `B-widthB*v`, `B+widthB*v`, `A+widthA*v`.
5. Test four oriented XY edge crosses in order: `(Q.y-A.y)*(B.x-A.x) - (B.y-A.y)*(Q.x-A.x)`. If every cross is <=0, accept immediately. This branch does not test Z, radius or the separate height. Degenerate repeated-point strips can therefore pass this containment branch after broadphase; a conventional nondegenerate polygon rule would change behavior.
6. On the first positive cross, test each quad vertex through `140f4ac50`. It requires vertex-to-query XY distance² <= query radius² and **vertex.z <= the separate scalar operand**. That scalar is not added to Q.z and must not be silently called a symmetric vertical extent. The helper's return uses SETNC for ordered greater/equal comparisons; NaN handling requires native-state qualification.
7. If no vertex passes, test all four **closed quad edges** through `141116580`. This is full XYZ squared distance from Q to a segment, compared inclusively to query radius². It is separate from the open point-path traversal. The segment helper takes A, delta B−A and precomputed length². Projection <=0 uses distance to A; projection >=length² reconstructs A+delta and uses that endpoint; interior uses `max(distance_to_A² - projection²/length², 0)`. No height scalar participates in this final branch.
8. The first accepting strip accepts the resource. Otherwise the next 48-byte region is tested. Failure of all regions rejects that resource in this source, without proving rejection from another source or the atmosphere/biome contributions.

The normalization and rotation use separate column products/additions, including zero products; the implementation retains these rather than collapse an idealized vector equation. It uses the native sin/cos **results for this fixed operand**, independently calculated from executable constants with the instruction operation order. Angle bits `bfc90fdb` are at static VA `144f052b0`, original file offset 82,856,112 (bytes `db0fc9bf`). Native polynomial outputs are sine bits `bf7ffffe` (`-0.9999998807907104`) and cosine bits `b4000000` (`-1.1920928955078125e-7`). All 18 constants, original file offsets, original-byte hashes and scalar reproduction are in local `.local-work/resource-milestone-b-spatial-constants.json`, SHA256 `792288db6c019e033885c9044e21c902fed526cdcf199b3489209ca7b36e025f`, produced by the adjacent original stdlib script. This is a static arithmetic reproduction, not a native runtime measurement.

## Discriminating evidence and practical limits

Existing final native sets discriminate the final UI fold and demonstrate the Iron/Alkanes/Helium-3 transitions. They do **not** discriminate a single-point broadphase from strip containment, vertex-height acceptance, 3D edge intersection, source changes or cache retention. Synthetic tests exercise those alternatives and preserve deliberately surprising degenerate/height behavior, but cannot validate actual native branch coverage. Scientific confidence is STRONG for this static algorithm transcription, while runtime branch coverage and native spatial equivalence remain NOT TESTED.

The narrow sufficient future acquisition is a complete same-evaluation census of occupied ProcGen source/resource maps, each complete 48-byte region and its point sequence, resolved IRES identity, indexed query and actual translation table, query radius and separate height, cache refresh/hit decision, plus the independently observed resulting first population and final UI rows. Zero/one/multiple-point alternatives and transition contexts should be characterized from that corpus, without inventing a fixed event quota. A callback acceptance decision or independently observed native insertion is needed to validate per-region branches; the evaluator's own decisions are not an oracle. A complete final region representation avoids requiring full terrain generation. No observer implementation or live action is authorized by this recommendation.

## Executable controls and limitations

`evaluate_region(query_xyz, query_radius, height, region_center, region_radius, points, *, point_count=None)` returns `sor-resource-spatial-result/1`, KNOWN/UNKNOWN, accepted bool/null, branch, reason and diagnostic provenance. Points are complete `[x,y,z,width]` rows; `None` is unavailable, `[]` is an observed empty sequence. A separately qualified `point_count` permits broadphase/0/1-count evaluation without reading unused points. Contradictory count/sequence, malformed vectors, nonfinite/subnormal operands and unqualified arithmetic yield UNKNOWN. Negative radii/widths are rejected from the qualified input domain, not claimed native negative-input behavior. This conditional single-region evaluator does not establish complete candidate enumeration.

Nine focused synthetic tests cover strict/inclusive broadphase and count alternatives; height-independent containment; absolute vertex height; 3D edge inclusion; endpoint/interior distance; polynomial rotation residual; no implicit path closure; malformed/missing/overflow/underflow UNKNOWN; and repeated-point degeneracy.
