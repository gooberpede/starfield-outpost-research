# Stability and lifecycle discriminators

[Native contract](native-contract.md), [D1 hypotheses](../disappearing-deposits/hypotheses.md),
[lifecycle primary windows](../native-availability-map/region-lifecycle.md).
These are concrete alternative causal paths, not a claim that a runtime bug exists.

| Mutable or selected state | Supported mechanism / test |
|---|---|
| Effective owner/frame/source | Manager/context setup, alternate descriptor and source index can select different frames/sources. Compare exact manager owner, descriptor/chart/translation, selected source/key and definition identity; same body name is insufficient. |
| Family/weights/order/settings | CTPerBiomeData/current/alternate RSGD and map readiness affect generation; ties/prior competing resources change rejection. Compare effective operands before geometry. Uniform masks in the frozen ordinary sources constrain that particular first-query weight alternative, not every boundary/context. |
| Attempted but unsuccessful population | Provider inserts cache entry then may take prerequisite early exit; visited records attempted source. Compare producer prerequisite/result and population extent before treating visited/hit as completion. This can explain missing regions in principle, not creation of replacement Copper by itself. |
| Reset/replacement/reuse | Explicit reset clears maps/visited; destruction distinct, exact travel/load binding unmeasured. Compare positively joined lifecycle events and content/population epochs. Same pointer after a load can be another object. |
| Partial readiness | Resource-server requests/neighbor tasks and publication are distinct from a global completed census. Mapped consumer lock excludes simultaneous partial writes by the mapped producer, but a completed early-exit/partial logical population can still be consumed. Record DB state/attempt status; do not claim an observed race. |
| Retained operation list | Refresh guard checks reference/domain/XY threshold; ATMO/BIOM lists refresh on identities. Radius/upper not independently in that guard. Record guard and exact list-production epoch feeding selected gate; fresh screenshot timing does not certify it. |
| Different consumer | Point disk/max-width segments, area tapered strips/singleton shortcut, raster, list and complete placement differ. Same regions plus different result requires the exact consumer/footprint/property branch and per-use operands. |

Comparison outcome protocol: same inputs and same consumed population with same
result is stable evidence for that sampled pair. Changed effective inputs support
an input-selection explanation. Identical generated output but another consumed
population supports selection/epoch divergence. Failed prerequisites/readiness
with an incomplete population supports readiness failure. Same inputs/paths/
consumed epoch but differing native classification isolates consumer operands or
predicate; differing gate/UI with stable region decisions isolates list/selector
or other admission/UI stages. Unknown epoch makes that comparison indeterminate,
not proof of instability. Stable pairs remain useful without triggering a rare event.

D1 establishes equal saved site fields across Save51/52 and extractor coexistence,
not the timing or occurrence of replacement. New evaluations cannot retroactively
identify the historical incident. No mandatory travel loop, rare-event hunt,
unlimited repetition or root-cause investigation is proposed.
