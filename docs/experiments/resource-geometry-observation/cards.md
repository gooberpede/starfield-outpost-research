## Replay order and numeric policy

Compare actual operands to frozen predictions before changing anything. First
compare case/frame/source/owner/component/selected definition/settings/order and
prior-state inputs. If different, report first material input disagreement;
replay measured inputs in a new receipt without retrofitting the frozen file.
Second run the accepted RG1 evaluator/dependencies without fitting, preserving
complete ordered sources/paths including outside starts and competing resources.
Compare generated source/resource/cell/ordinal/point-count identity exactly and
IEEE binary32 point/bound words exactly for a claimed native-order replay.
Retain absolute errors; the inherited0.01 alternate-arithmetic tolerance is only
a diagnostic comparison, never permission to convert presence or branch mismatch
into agreement. No tuning of epsilon/seed/frame from observed results.

Third compare generated output to the exact consumed population and positively
joined generation/population epoch. A whole-generation population match requires
complete relevant collections, including rejected/unused paths; short-circuit
captures alone cannot certify this. Fourth replay actual consumed geometry and
branch-specific query/radius/absolute upper, then compare actual region terminals,
area-resource fold and selected extractor gate separately. Missing or varying
per-use values block single-query replay, not all scientific use of evidence.
NaN/infinity/subnormal/overflow or unsupported MXCSR modes remain UNKNOWN under
the accepted evaluator domain; signed zero retained. Exact native branch results
and disagreements remain evidence even outside model admission.

Any proposed evaluator correction requires new versioned source/prediction files,
preserved failing examples and fresh tests against held-out IL/Iron/Copper plus
relevant Kreet P1/P2/R1 controls. Existing v1/v2 files remain byte-identical.
Manual fallback uses screenshot/reticle/landmark uncertainty and displayed failure
reason, not these numeric equivalence rules: it can falsify a list-only account
when a local placement/resource discrepancy is established, but cannot identify
which source/epoch/seed caused it or validate exact native polygons.
