## What the ship/player contrast means

The new operator reports are two manual sequences, including restart/reload,
without SFSE. Local SOR-002↔SOR-003 travel often retains the ship at its current
landing area; arrival from another Kreet area selects LZ3 for SOR-003 and LZ1
for SOR-002. First and repeat player arrivals differ, and a conventional POI pad
can remain empty. [M01–M08](manual-observations.md) preserve each statement and
its evidence grade. No distances or LZ labels are new native measurements.

The native evidence supports separate landing-route resolution and player travel
command construction/consumption. `1417DEC70` resolves the relevant ship/target
state, computes a state-dependent command decision, calls 78B030 for a landing route,
then constructs a separate command. Decision byte **command+8D**, preservation
byte **+8E**, target/reference handles, world/angles and arrivalXYZ are distinct
fields. The decision is ship-related, but is not proved to mean "move ship" by
itself. When reached, `141A67830` hands command state to player+A08;
the decision 0/prior-ship/manager branch can skip this handoff after 789850.
`1417DF210` consumes command
conditions. The [specialist ledger](specialist.md) provides exact predicates,
alternate routes and decisive instruction windows; this is static execution
semantics, not proof which branch any manual sequence used.

This architecture is consistent with the reported contrast, but does not uniquely
explain it. Differing command/ship-selection state, resident-world reuse, same
marker re-selection, destination eligibility and loaded overlay state can each
change visible placement. A route may calculate even when the ship stays put;
visible movement may reuse an existing marker. Player arrival in front of the
ramp versus elsewhere can come from differing arrival/reference modes without
new marker generation. The previous 040 capture did not observe these command
fields, so it cannot retrospectively decide the alternatives.

## Shared arithmetic and the stronger Workshop path

The landing route floors **marker-local** binary32 XY after multiplication by
binary32 .01. Both floors are 0 in the actual capture. It stores residual plus
terrain translation: localY 50.43891143798828 becomes routeY 2150.43896484375.
Feeding the translated Y back into this call as floor 21 would invent an input.
Fresh 96EB90 supplies the 44-byte descriptor for the final landing angles;
96F5C0 offsets it in place. With resolution 256 and block 10+merge 2, the native
numeric result is **[1,10464,21141]**, exactly the frozen component replay.
All descriptor bytes remain unchanged on this zero case; incidental RAX is not
the output. No compensation helper runs in this marker route.

`AD0B90` is more directly useful for Workshops: type/keyword eligibility precedes
`F4AB80` compensated-center production, context translation is added to XY,
binary32 scale/floor supplies signed integers, and **the same 96F5C0** consumes
the candidate source descriptor. Its radius-derived bounds and latch then
participate in candidate rejection. This connects ship landing assessment to
ordinary Workshop positioning without pretending the marker's local XYZ equals
the Workshop center. The actual 040 capture contains 40 E enumerations but **no
instrumented callback/center/grid records on this Workshop path**. Empty or
filtered collections and source/list state remain alternatives; Q return 1 alone
cannot discriminate them.

96F5C0's shared integer branches include signed C remainder modulo 49152,
positive/negative wrapping, face xor1 for X/xor3 for Y/xor2 for both, and
coarse/sub/fine decomposition at 192/12. Changed coarse/sub/tag can refresh opaque
landscape/pattern handles; tuple arithmetic alone cannot validate those handles.
Packed tag 2/3 axis reflection is a separate conversion. Angular quantization,
landing snapping, native FP environment and future loaded frame selection are
also separate from this shared offset component.

callbacks concern candidate footprint terrain admissibility, not directly an
ordinary Workshop radius. The separate AD92E0→Q→E→AD0B90 route contains a
recoverable Workshop overlap test: effective radius from F38E30 is scaled/floored
