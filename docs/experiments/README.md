# Experiments

No experiment has been executed in this project. Use [the template](../templates/experiment.md), [the evidence standard](../EVIDENCE_STANDARD.md), and [WORKFLOW.md](../../WORKFLOW.md).

Use `SOR-EXP-0001-short-topic.md` and allocate IDs sequentially. Record status as `PLANNED`, `AUTHORIZED`, `RUN`, `ANALYZED`, or `CLOSED`, with actual dates and scope. An authored plan is not authorization and a completed run is not a proven interpretation.

A record must contain the question, scope, sources/permissions, actual baseline and samples, control/comparison, exact approved actions, instrumentation/side effects, observations, interpretation/alternatives, counterexamples, validation, deviations, stop/cleanup, evidence hashes/locations, and next bounded step. Record runtime and save observations together where they concern the same concept.

Keep failed/negative runs and superseded interpretations. Link conclusions into the subsystem and finding/state/function registers. Do not promote a claim simply because bytes differ or a test reports success.

Raw data stays local. Selected, reviewed bundles go in [evidence/](evidence/README.md) with their own authored README and rights/integrity metadata. Plan any live work separately; no live run follows from this directory existing.
