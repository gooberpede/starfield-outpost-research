## Findings, corrections and exceptions

The initial population-count expectation was corrected scientifically from the
actual two-path delta before finalization. The final prose explicitly separates
resource membership from equal path counts, chance admission from surviving
geometry, source ordinal from stable identity and C1G's new epoch from C1E history.
No certainty is upgraded through editorial wording.

The first automatic screen flagged structural CSV commas as missing prose
spacing. CSV parsing now separates fields and exempts explicit path/hash/ID
columns; the added fixture checks both readable labels and actual joined prose.
Final CSV labels and locator identities are still manually inspected. The eight
editorial tests pass and the final screen has zero diagnostics.

Manual numeric review corrected an off-by-one configuration-file count in the
draft prose: the 63 pinned inputs are one EXE, 39 plugins and 23 configuration
files. The underlying audit/output already had the correct inventory. Every
summary and table now uses 23, verified against the exact path list.

Intentional identifiers, exact hashes, literal source keys, filenames, raw bit
patterns and code examples retain their spelling. The checker excludes inline
symbols and code fences for that reason; manual review checks their domains and
uses. Deliberately corrupt fixtures are test data. No inline suppression is
needed for the final changed prose. CSV/generated JSON fields are inspected for
readability and identity; the regex checker does not interpret opaque payloads.

Automatic diagnostics, any corrections after the first screen, and the final
manual/independent coverage are retained with the local review returns. A clean
scan is necessary and insufficient: scientific semantics, concatenations without
obvious token patterns, table structure and link meaning require actual reading.
The tool's bounded limits are explicit in the standard and tests.
