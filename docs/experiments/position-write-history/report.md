## Mechanism and feasibility

The [audit](static-audit.md) independently recovered the initial saved-created
setter path, all evidenced direct setter/scalar/center callers, post-inner-call
d3 ordering, genuine queued command application and actual setter bypass stores.
B4E410 can skip equal-value stores; a setter event is an invocation, not proof
of a write or object birth. B73310 receives 16 bytes including mode; original
pointer operands and R8/R9 are forwarded. Ordinary B734C0 capture surrounds the
actual virtual target, including its later mask 02 update. Other subclass slots
remain unqualified and unpatched.

The earliest selected restoration setter 5A14DA can precede Workshop ExtraData
identity. All relevant generic events are retained, rather than early-filtered.
Retrospective pointer segments acquire later coherent IDs as **candidates**;
observed ID/FormID/base changes split them. Unobserved same-ID pointer reuse
remains uncertain. At the queued allocator's natural return, RAX is the actual
command and TLS supplies its actual queued producer. Application 18CE315 exposes
that command as original R8−10, including raw ref/parent/vector. A cross-thread
application retains its own TLS parent; command linkage is a separate relation.
Allocation precedes publication and does not prove successful enqueue.

Seven natural F4AB80 CALLs copy reference/compensation/output independently.
No native lookup or center function is artificially invoked by the observer.
Own cell/world samples are distinct from any enclosing frame. Unknown handles,
body resolver, selected edge producer and saved remapping remain unavailable.
Early generic history can isolate an observed signed vector/replacement before a
later center, but cannot fill missing direct writers or lifetime epochs.

The same guarded complete-CALL/sole-thread SFSE admission mechanism reached
READY in prior 050 retail evidence: local
`.local-work/native-oracle-live/session-17008-144157125/admission.json` records
sole_thread_observed=true and startup_wait_ms59360, followed by 1194 persisted
events and normal retirement. This is sampled prior feasibility, not 060 retail
validation. Fresh 060 verifies pinned installed PE and each CALL target/preimage,
and guards target entries/owned sites at runtime. Fresh admission receipts make
the actual gate inspectable. Expected Steam/NVIDIA overlays are recorded and
accepted; demonstrated site conflicts fail. No blanket module allowlist.

Sequence orders serialized emission after sampling, not actual native stores.
QPC is sampled before snapshot reads; the native operation lies between its
before/after records. Overlapping cross-thread calls therefore give intervals,
not an exact total order of XYZ stores. Caller ancestry means audited CALL-site
RVA and genuinely enclosing instrumented TLS scopes, not a complete native stack.

## Lossless transport and intervention

The first design flushed raw+journal per event. Its native fixture exposed
unacceptable throughput: only about 800 records after several minutes. That
disposable run was explicitly interrupted; its incomplete artifacts remain.
The corrected design uses serialized cached WriteFile calls and periodic group
flushes under the same lock. OS writeback supplies backpressure; there is no
bounded queue, enqueue retry drop, event quota or arbitrary size/time cutoff.
No observer lock spans a native call. The worker flushes already owned bytes
without requiring an engine callback/lock; module enumeration is outside capture.

Captured raw+journal writes and last successfully group-flushed sequence are
separate. A crash before flush may lose a suffix; a crash after flush preserves
the qualified prefix. Partial raw-before-journal writes are retained and located,
not repaired. Real WriteFile/flush/guard/disk failures close new admission while
pending calls finish where possible. STOP does the same without labelling healthy
optional read failures or unusual values as failure. Resident hooks remain inert
until normal exit, not dynamically uninstalled.

The worker maintains append-only health, fresh nonce ACKs, admission/patch/module
receipts and explicit retirement/failure counts. A preallocated 4096-byte
failure-only emergency page records terminal/disk-query failures without growing
the file; failure of that channel leaves an explicitly unconfirmed terminal.
The four-byte preallocated STOP flag remains operable when protected checks or
disk queries fail. These mutable control/status pages never rewrite raw evidence.

Raw/journal and health/ACK writes reserve their pending D: bytes above the absolute
40,000,000,000 caller-available-byte floor; C: must independently satisfy the floor.
Queries fail closed. Hooks, snapshots, serialized writes and group flushes change
timing. Disposable speed and prior 050 feasibility cannot guarantee retail timing
or stability. No patched gameplay fields, reference-count manipulation, fabricated
calls, register edits, debugger attachment or exceptions suppressed.
