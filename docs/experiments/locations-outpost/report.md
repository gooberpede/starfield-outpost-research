**Locations combines an entry snapshot with separately selected body metadata,
a schematic system hierarchy and a projected galaxy-marker array.** Its numeric
badges copy the common Workshop cache. Selection repaints those copied values;
it also requests body metadata using the entry's body ID. These operations do
not establish one atomic or continuously fresh screen state.

| Question | Best-supported answer |
|---|---|
| Cargo Links | Reuse BM2: qualifying resolved, non-disabled, active local cargo endpoints among reverse WorkshopItem members. This can differ from built-pad quota, paired-route totals and operating freight. Locations binds that same cached integer. |
| Crew | Reuse BM2: CrewExtraData assignment handle-list length, without resolving each actor at display time. Capacity, physical presence and skill participation are different quantities; robots are not categorically removed from this list. |

| Faction | Selected body's containing system resolves to a location context; its owner search can climb parents. Preferred owner pointer +d8 overrides definition owner +a0.
