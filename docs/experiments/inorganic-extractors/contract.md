# E1 offline research contract

2026-10-16, Australia/Sydney. SOR-EXP-0038 / SOR-EV-0046.
[Original authorized brief](../../implementation-briefs/CODEX_BRIEF_SOR_E1_inorganic_extractor_native_mapping.md).

The eight capabilities in brief §2 are mandatory research questions, not eight
promises of runtime validation. Deliver a useful descriptive native reference,
an explicit mapped/inferred/unresolved matrix, source and input pins, D1
cross-checks, independent review, preservation receipts, prose/link checks and
complete/task-only textual patches. Original criteria remain unchanged.

Allowed actions: read existing archived save evidence, installed definitions,
pinned executable and existing analysis state; export selected existing native
functions through the owned Ghidra reader with `-readOnly -noanalysis`; author
documentation and narrowly necessary offline verification. Outputs are authored
review-required files and ignored local receipts/exports. No target invocation,
game/process access, instrumentation, deployment, save modification, database
content edits, new dependencies, network disclosure or Git mutation is allowed.

Routes, in order of information gain: reuse the controlled extractor and owner
joins; qualify definition family/model exceptions; follow current-state consumers;
follow production reason/timer/creation and directional transfer functions.
Fresh whole-save decoding is unnecessary when the question is an already
qualified identity and the original archive bytes still match. Direct definition
record checks and native instruction windows independently qualify new claims.

Risks are mistaken pointer/handle/FormID domains, decompiler signature errors,
display caps and incorrectly equating saved state with current output. Stop the
affected route on pin mismatch, database lock, script error, unresolved identity
or inadequate instruction coverage. Preserve failed/partial exports and historic
interpretations. Keep C:/D: free space above 40,000,000,000 bytes for sizeable
verification writes. No raw originals are cleaned up; disposable review trees
remain local. Inspect actual logs rather than treating process exit as evidence.

COMPLETE requires adequate contracts for every agreed capability. CONDITIONALLY
COMPLETE requires a substantive usable map with explicit current/effective-state
limits. INCOMPLETE / evidence-bounded must identify consequential missing
contracts and the smallest further evidence, after pursuing useful authorized
offline leads. A failed locator is not absence or impossibility. Do not expand
into organic production, switch logic, inventory counts or a simulator.

One primary implementer, one focused read-only saved-identity specialist and a
fresh-context independent reviewer are authorized by brief §6. Reviewer challenges
classification, power/activation separation, direction, production quantities and
completion. Reviewer acceptance does not authorize integration or publication.
