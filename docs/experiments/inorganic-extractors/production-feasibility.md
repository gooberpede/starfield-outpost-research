**REVISE.** A worthwhile, discriminating test remains, but saved controls and
an observation contract are insufficient for GO. This is a completed feasibility
assessment, not a request to implement instrumentation. Arithmetic-reference
completion is separately CONDITIONALLY COMPLETE.

The consequential question is whether assignment/list construction selects one
effective crew contribution or supplies multiple actors whose qualified entries
then compose. Static timer consumption proves a fold over eligible supplied
actors, but does not prove the actual ExtraE2 membership, deduplication or active
rank-selection policy. A gameplay claim about stacking depends on that boundary.

| Test element | Minimum useful contract |
|---|---|
| Hypothesis A | Two assigned actors with the relevant Management perk supply two eligible contributions and both multiply the interval. |
| Hypothesis B | Assignment/list or active-entry selection supplies only one effective contribution (for example replacement/strongest selection); the second does not reach the timer fold. These are alternatives for a qualified contrast, not an exhaustive model of every perk. |
| Minimum practical observation | At actual `140f7bd20` consumption, correlate Workshop/resource/producer, the consumed ExtraE2 handles and resolved eligible actors, relevant actual active A1 entries/condition outcomes, per-actor interval input/output, player contribution, effective harvester AV and final row+14 interval. Pair a baseline with an assignment contrast at the same producer/resource and unchanged player/perks/AV. Merely recording the final interval cannot locate selection versus predicate failure. |
| Suitable controls | Candidate S4/Save12 for linked iron and room for output; S3C if transfer is unnecessary. Neither contains a qualified crew contrast. Establish two relevant actors, their actual ranks/active entries, assignment membership and eligibility under separate authority. Do not assume spawned/configured actors or change perks under this brief. |
| Ideal success | Two proven eligible contributions, each changing the consumed float, with matching final stored interval, supports A for that contrast. A demonstrated upstream selection of one despite both assigned, with coherent consumed state, supports B within that policy/context. |
| Counterexample | Both qualified actor contributions are consumed but the final row differs after accounting for player/AV: the mapped reset/context contract is incomplete. Preserve exact operands and branch ancestry; do not explain it away as timing. |
| No signal | Missing calls, changed resource, failed actor conditions, no working baseline or unqualified assignment means inconclusive. A zero delta alone does not select B. |
| Cost/risk | Requires new observation of assignment/active-list consumption, scalar dispatch operands and a correlated row write. Existing locks/reference ownership, actor/Extra lifetime, virtual calls, thread affinity, reentrancy and callback argument lifetime require qualification. Hook/callback instrumentation can alter timing/execution. Do not retain borrowed pointers across callbacks or infer safe access from an address. |

Why existing captures cannot answer it: 0.7.0's continuous unplaced beacon-preview
captures qualify resource-list/UI-consumer agreement. They do not observe
installed-producer timer actors, active perks, effective AV, row reset or
inventory insertion. Earlier E1 has static instructions and saved rows, not this
runtime contrast. No existing hook is qualified for these new reads. A new
instrumentation/review brief would be necessary; none is implemented here.

Before GO, qualify the control's actual producer operation and an assignment
contrast without arbitrary edits, prove a coherent/lifetime-safe observation
boundary, define bounded capture completion/stop/cleanup and independent
verification. The [conditional S4 restoration fragment](production-saves.md)
belongs in that future card if S4 remains selected. No arbitrary runtime or record
quota substitutes for observing the two consumed cases.

A separate quantity test is deferred: requested insertion count versus actual
inventory delta could settle downstream creation limits, but needs a qualified
insertion/result boundary, destination/resource identity and capacity controls.
Adding this to the actor test would dilute its minimum observation contract.
Do not count ItemProduced event alone as proof of inventory delta.

**NO-GO for a multiplication-only probe.** Perfectly collecting two scalar inputs
and the VMULSS result would repeat already pinned arithmetic while leaving actor
selection and realized output unsettled. Its engineering/lifetime cost buys
little consequential evidence. The recommended REVISE test earns its value by
discriminating actual participation, not by confirming that multiplication ran.

No live action is authorized by this classification. Even a future GO would
