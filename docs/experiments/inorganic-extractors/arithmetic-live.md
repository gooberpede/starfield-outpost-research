# Scientific value of possible live validation

This is a separate assessment under the [offline brief](arithmetic-contract.md),
not authority to implement an observer, restore a save or run the game.

**NO-GO for a live repetition of the ordinary crew-stacking or hundredth-format
question.** Selected-rank replacement, distinct-actor composition, shared UI
cache and the installed two decimal algorithms are now supported statically.
Capturing a number near 1.666… again would add little scientific value. The
historical [crew proposal](production-feasibility.md) remains preserved with a
prominent supersession notice. Its original REVISE outcome is historical.

**REVISE for a future small realization/elapsed-state validation.** The remaining
consequential question is whether a particular loaded, working ordinary Iron
extractor follows the mapped requested-count/reset contract across frame and
wait updates, including output acceptance. An ideal offline result settles
the code's operands, clock conversions and conditional behavior, but cannot
supply that outpost's actual effective AVs, current eligibility, insertion
result or executed path. No ready matched working control is established by
the screenshots or the archived filenames alone.

| Competing explanations | Smallest discriminating observation | Expected conclusion |
|---|---|---|
| A displayed nominal rate accurately predicts output in a qualified empty destination; versus eligibility/capacity/state separates it from realization | A verified working control with stable known modifiers; record starting/ending destination counts over a defined interval while keeping the displayed rate and output route fixed | Agreement supports the named control only; disagreement requires consumed interval/reason/request/acceptance evidence rather than changing the native formula to fit. |
| Frame elapsed and explicit skipped-time updates execute the traced distinct batching/reset paths; versus a different active caller/state supplies the elapsed | Same control, separately defined ordinary-play and one wait action, with calendar scale/local conversion documented; preferably capture the existing native caller's elapsed/countdown/request operands if visible counts cannot discriminate | A complete consumed-operand observation decides executed-path membership; visible totals alone may remain ambiguous because reset/acceptance can coincide. |
| UI cache is promptly refreshed after one eligibility change; versus delayed/coalesced refresh or retained cached eligibility | Same outpost, one reversible power/eligibility change, compare the two screens at documented epochs and allow their normal refresh | A change identifies a scoped refresh response; a persistent label does not establish ongoing output or a broken global scheduler. |

A broad observer collecting every producer, inventory and clock is unjustified.
Manual visible counts are the lowest implementation cost but may have weak
discrimination. If consumed operands are essential, a new bounded instrumentation
design must justify hook location/lifetime, coherent copied fields, instruction
guards, interventions and implementation/qualification cost. None is designed,
built or deployed here. Breakpoints/hooks could disturb timing and must be
disclosed, not called non-invasive.

Controls are not yet GO-ready. The screenshot state is not a known saved file.
The existing [save analysis](production-saves.md) identifies S4 as protected
**Save12**, not literal Save4; S3C is another simpler candidate, not a demonstrated
working live control. This assessment does not choose S4, so no new S4 run card
or restoration is issued. If a later proposal selects it, the brief requires
fresh path/hash/configuration/menu-label verification, exact backup identity,
destination collision checks and explicit metadata-preserving safe restoration
steps in that approved card. Do not restore anything now.

Any future proposal needs a specified build/sample, actual usable control,
precise predictions, meaningful stop/cleanup conditions and explicit live
authority. These costs and present control gaps justify REVISE; they do not
weaken the established scoped static results or justify gathering redundant
telemetry. D1, organic eligibility, full builder mechanics, production networks
and general inventory reconstruction remain outside this assignment.
