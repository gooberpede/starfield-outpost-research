# Cross-game geographic identity

2026-10-20. SOR-EV-0066. [Answer](report.md), [native/source register](sources.csv), primary `.local-work/coordinate-sufficiency/native/006–013.request.tsv`.

**The same ordered planet/terrain definitions, style relationships, load order and terrain settings support the same addressed geographic region and base-terrain selection in another character.** This is a scoped STATIC inference, not a measured fresh-character landing. Save-specific dynamic world tokens are instances at an address; they are not the address itself. The fixed Lab definition independently anchors this region across characters using installed PNDT/WRLD identities.

## Positive dependency chain

There is no character parameter in the recovered seed or candidate-filter path. The filter preserves registered-table order; the same definition set/order and style relationships therefore belong to the repeatability precondition. This is positive evidence for ordinary repeatability, not an argument that the entire engine lacks every mutable state. Same executable version alone does not ensure identical mods, definition lists or overrides. Configuration-file searches found no relevant installed-game seed override; historical effective settings are not retrospectively measured. Reuse should qualify the same definitions and terrain settings. Runtime-created/edited terrain definitions are not included in the ordinary unmodified-data claim.

The first independent review correctly rejected treating a fixed seed alone as a complete dependency argument. Its concrete missing stage was the candidate-filter/population above. That stage was then inspected directly, rather than assuming that all selection inputs were stable or widening the task to general procedural generation. The first REWORK and follow-up evidence remain in the review package.

## Real variable content and practical limits

`1418a9270` separately initializes Planet Content Manager+420: explicit `iPlanetContentManagerSeed:Planet` value at 145e8f2b0 if nonzero, otherwise a draw from a different global PRNG. It publishes `pcm_seed` and initializes its own generator. `14004eae0` initializes that setting's default to 0. This is a **real alternate source of variation**, distinguished from the deterministic surface-tree seed. The current task does not reconstruct all downstream PCM consumers or promise identical randomly placed POIs, clutter, encounters or player alterations. The exact division of fine mutable dressing from immutable terrain is not an exhaustive census.

An equivalent address identifies the same geographic region; a saved dynamic token or incidental landmark name does not. The Lab's installed fixed-world definition supplies a stronger repeatable landmark than those random POIs. This task does not observe a fresh character, invoke a location API, select a new landing, or prove that the landing UI can target a particular 100-unit cell. Landing-origin snapping has its own 96-step interior rule and boundary exceptions; it is not the precision of the stored geographic grid.

No new live experiment is needed to retain the supported regional address. If actual gameplay recreation is desired later, the minimal separately authorized test is: on the same pinned data/settings, compare the addressed region near the fixed Lab in a fresh disposable character, record the selected landing's descriptor/anchor and two recognizable terrain features, and report landing-selection precision separately from terrain correspondence. This is a proposal only; no game load or new save is authorized here.
