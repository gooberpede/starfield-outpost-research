## The missing upstream choice was a loaded tree

The earlier model reconstructed a new surface tree from installed BIOM values,
SFPT record order and default settings. That is a real native generation path,
but not the only route supplying a tree. PNDT has an independent FNAM reference
outside its BDST section. Its typed resolution installs an existing SFTR at
PlanetData `+0x38`; the ordinary getter returns that tree. Fresh generation is
conditional on its absence and a creation request. [Exact boundaries](native.md)
distinguish these alternatives without claiming that the historical invocation
was recorded.

The pinned main ESM contains 1505 SFTR records. An initial bounded type inventory
exposed this previously omitted source class. The final predictor follows the
PNDT FormID reference, not an editor-name search or a geometry score. Carinae's
referenced tree supplies `0x00212e16` at native index `111*256+81`. This is an
independently recoverable upstream definition value; it is not the observed
source's `+0x44` field passed back as a prediction parameter.

Two predictor runs produce identical complete tables and selected traces. The
predictor modules have no capture-reader dependency or expected-SFPT argument.
The validator opens the closed predictor artifact, checks its hashes, and only
then loads the native witnesses. Its separate before-inventory diagnostic still
uses the historical retained-pattern witness to reproduce C2C's coverage state;
that witness does not populate the new predicted table.

The failed generation control remains informative: raw CRC operands
`0800000005cd010015122020`, MT seed 4277502381, draw ordinal 44655, word
3969642406, uniform 0.9242451786994934 and candidate index 4 select
`0x00212e19`. No registry permutation, seed search or special Carinae branch was
introduced to change that result. The linked-table lookup consumes no candidate
