An output link is a direction of access, not a scheduled conveyor belt with an
independent fixed rate. The native operations use the directed graph to find
reachable storage. A chain can supply a final store directly without first
materializing every item at every intermediate inventory. Forks compete in the
current cached vector's reverse order; hash/set iteration and cache rebuilding
mean that the save does not establish a stable first-linked priority.

The ordinary mover never selects an upstream inventory as its receiving
destination. The script-facing refill operation may enumerate upstream **sources**
after a player removes stock from a receiving container, but each selected source
still moves downstream. Direct production, ingredient consumption, manual access
and cargo arrival/return are different writers. A full container or mixed cargo
stock is not evidence of reverse flow. A deliberately reciprocal graph has two
directed paths; traversing its other edge is not reversing the original edge.

Fullness has two mechanisms. Redistribution filters each current item and plans
up to its positive-weight floor-fit quantity. Rejected or unplanned units remain
upstream; there is no reverse spill to upstream stores in this path. Production
selects a store using an already-full check and can add a whole batch across its
nominal capacity, as accepted S1 establishes. Also, redistribution plans all item
rows before execution without aggregate weight reservation: per-item fitting is
not a universal whole-batch capacity guarantee. [Traces](traces.md) retain this
counterexample and the actual exclusion-set comparison.

There is a positive remote delivery mechanism: frame, wait/sleep and travel
elapsed calls traverse the registered Workshop set and producer rows. Successful
current eligibility reaches the same downstream selection and creation path.
TESObjectLoadedEvent's false branch refreshes a matching row rather than deleting
it. Thus graphic unload alone does not impose return-only catch-up. A whole
unresolvable/unregistered Workshop receives no row updates in that invocation;
an individually unresolvable producer accumulates bookkeeping after losing its
handle; an ineligible resolved producer normally resets its timer without a
recoverable due-cycle debt. Those outcomes must not be merged into one promise
that every remote outpost always runs or always catches up.

| Object | Existing-stock local operation | Production/input integration and boundary |
|---|---|---|
| Inorganic extractor | Own inventory can source redistribution; incoming links prohibited by ordinary policy | Creates at downstream store or own buffer; full own buffer can still produce when a reachable store is nonfull; power/halt checked for production |
| Greenhouse/husbandry/fabricator | Own product inventory can source; builder references are excluded as ordinary downstream storage relay targets | Recipe inputs counted/removed transitively upstream; one selected output store, own-buffer fallback; recipe shortage bounds cycles; organic catalogue/knowledge differences remain E2 |
| Dedicated storage | Sources and receives eligible item stock; can be traversed to further storage | No power/halt check in the ordinary movement or downstream container predicate; capacity and item filter apply |
| Transfer Container | Generic local inventory plus player/menu source-reported triggers | Local graph behavior shared; ship menu access is separate, not an automatic cargo pump |
| Fueled generator/pad fuel marker | Logical incoming ingredient consumer; not a demonstrated physical receiver inventory or ordinary relay | Consumes He-3 from reachable sources through shared recipe path; electrical state/charge separate; voyage fuel deferred |
| Cargo incoming/outgoing children | Separate reference inventories; incoming can source local movement, outgoing can receive and source subject to S1 pair gates | Incoming contents are usable local stock without a cross-outpost graph edge; shipment, flights, returns and He-3 freight deferred |

No power or halt predicate is imposed on passive storage by these ordinary
movement paths. Explicit disabled/deleted references may fail resolution or be
removed by another lifecycle operation; this is not a universal promise of
disabled-object survival. Graph construction restrictions and per-item movement
filters are different tests. Builders can consume an ingredient from an upstream
store without receiving that ingredient into their own product buffer.
