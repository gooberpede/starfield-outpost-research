## Implementable observation schedule

Use the repaired D4B controller after fresh qualification. In generation mode, DR0 retains updater-entry detection; DR1 observes generation entry; DR2 samples loop entry `0x1407bc470`; DR3 observes map return `0x14079b925`. On that return, switch DR2 to ordinary CALL `0x14079be20`. The next generation entry resets that schedule. Consumer mode uses the existing globally coordinated ACCEPT/REJECT/transfer schedule. Nested/unwound/interrupted generation invalidates the affected diagnostic chain; no borrowing an outer frame. This schedule uses at most four active hardware slots and needs actual phase-contention/queued-trap tests before admission.

Read map snapshots at loop boundaries and final return, then verify every reconstructed array transition against the next snapshot. At loop entry, RDI is not yet the current node: compute the node from the copied iterator as specified above. R15 is the map pointer in `0x1407bc3d0`. Do not reuse the D4B pre-exchange RDI/RDX interpretation at this different site. Qualify stack relations and expected return addresses in actual disposable fixtures: map function return `0x1407bc374`, wrapper continuation `0x14079b925`; caller frame F is not assumed merely from a prior diagram.

Engineering limits are 4096 entries per array, 65536 bytes per individual read and 1048576 bytes per framed sample. Validate pointer arithmetic, bounds, count ≤ capacity, occupied map inventory and stable rereads. Oversize, changed, partial or invalid data is explicit acquisition failure. These copy limits protect memory/evidence integrity; they are not event-count or session-duration quotas. Flush and independently reread each complete frame before numbered ACK. Missing/refused ACK cannot be counted as durable success.
