## Instrumentation assessment

Source contracts:050 `runtime/native-oracle-050/core.h` snapshots0xD0 bytes,
rechecks identity/base/extra-list and collects center data after native return;
060 `runtime/native-oracle-060/history.h:31–38,64–90` snapshots0xD8 and
brackets calls, rechecking the full prefix. Neither is atomic. Four incoherent
pairs are retained. Actual build manifests pin21 patches050 versus129060;
AD0C36 is in both, F4A1D4/F498F1 only060.050 has Q/E/callback/grid ancestry
that060 lacks. This demonstrated selection difference is separate from timing.

Complete CALL replacement/relay and pointer-slot patching preserve the original
target path. Environment guards restore FXSAVE/LastError; retained disposable ABI,
exception, reentrancy and transport controls were inspected, not re-executed as
new native tests. No observer source directly assigns game referenceXYZ or
invents native output. This excludes an intentional observer coordinate formula
in the audited code, not every possible ABI defect. AVX upper-state/implicit
contracts, sampled lifetime and retail behavioral noninterference remain limited.

050 uses bounded nonblocking queue publication to worker flush;060 `Spool`
acquires a shared exclusive SRW lock, hashes, queries disk space and performs
synchronous cached raw/journal writes on engine threads. Group flush holds the
same lock. No lock spans the native call, but before emission delays entry.
Long observed brackets establish instrumented elapsed delay, without assigning
that delay to native computation. Scheduling perturbation is plausible and has
a concrete mechanism; its causal effect on frame activation or XYZ is unknown.
Journal append order is not native cross-thread store order (fresh replay finds
60,264 adjacent cross-thread QPC inversions). No noninterference claim is made.

## Decision-ready acquisition assessment

Further live evidence would materially improve durable-position validation only
if it measures the missing joins. Recommend the same Save25 one-new-Kreet-landing
then return trigger that actually reached AD0C36, with a targeted observation at
that boundary: reference/base/FormID/WorkshopID, XYZ/compensation, D3, direct and
resolved own-parent/world, Q/E source key and descriptor, outputXYZ, and epoch
qualifiers. It would distinguish differing current state from absent coverage.
No guarantee of repeated reachability is implied.

To explain Z rather than merely repeat it, additionally observe the actual
AD1660/ACD180 producing edge key/validity/XYZ/height mode/epoch and reference
membership, plus the selected ordinary converter before/after flag and signed
vector or replacement writer. Preserve queued command generation separately
from TLS ancestry. If using a descriptor consumer as a comparison, record its
frame index, global count/table vector and input point/height ceiling: current
captures omit these. These observations have independent purposes; a current
query edge is not automatically the previous producing edge.

Automatic idle camera is a lower-priority acquisition question: record an actual
state transition/input inactivity and caller/job association only if still needed
after the static audit. Repeating many F4A1D4 samples would add little causal
information. Broad writer logging should not precede the matched consumer test.
Controlled timing comparisons become justified only once the same trigger and
boundary differ. An external debugger remains closed. Every proposal needs a
separate brief, hook/ABI qualification, protected saves, finite actions and explicit
live authorization. No observer source/build/deployment is part of this task.
