## Candidate format and reader checks

`c19-callbacks-v1.json` is canonical UTF-8 JSON with sorted object keys, compact
separators and one trailing LF. The format identifier is
`sor-d5be-c19-callbacks/1`. Integers are decimal, and runtime FormID strings
use eight lowercase hexadecimal digits. Stable run numbers start at 1. The
`callbacks` array is in raw entry record order. The `invocation`, `entry` and
`exit` fields identify the original callback scope and its one-based WAL record
sequences. A `model` token preserves equality for the set-change calculation.
Resource tokens preserve raw pointer equality across the derivative. Token zero
denotes null. Resource and model tokens occupy separate domains.

| Field | Ordered representation and source |
|---|---|
| `spatial`, `atmosphere` | Actual kinds 103 and 104 child `call` ID, `entry`, `exit`, population `header` sequence and `members`. Each member is `[sequence, pointer_token, form_id]`. |
| `biome` | Kind 108 header and kind 109 members for source 2 sampled on callback entry. This is a snapshot of the branch's candidate input. |
| `selector` | `[pointer_token, form_id]` from the kind 102 entry selector observation. |
| `append` | `[invocation, entry_sequence, exit_sequence, pointer_token, form_id]` per completed kind 105 child. An empty array is an observed zero-call census. |
| `rows` | `[zero_based_ordinal, constructor_invocation, constructor_entry, constructor_exit, final_census_sequence, pointer_token, form_id]`. The kind 106 constructor pairs with a kind 110 model-row record by ordinal. |
| `run` | Index of the stable-run context in `runs`. The candidate carries the population signatures, first and last preview invocation, count, and operator labels when available. |

From the repository root, use Python 3.10 or later and the standard library. The
[standalone verifier](../../../research/evidence-access/d5be/c19-verify.py) has
no private source dependency and writes no files.

```text
python -I -S -B research/evidence-access/d5be/c19-verify.py --self-test
python -I -S -B research/evidence-access/d5be/c19-verify.py c19-callbacks-v1.json --sha256 d37476dd5b33fca44423c1c0aaf239b43e8a98d8cf2ed97b15beaa4225906ada --negative-controls
```

The first command prints `PASS synthetic fold only`. Its invented inputs
exercise common deduplication, distinct pointers sharing a FormID, nulls, and
duplicate selected appends. The second command requires the exact candidate
file at the given path. With that file the verifier recomputes the comparison
from the operands, checks the observed row order and count, and expects
`comparisons: 346`, `rows: {"2": 7, "3": 339}`, `append_count: 0` and
`set_change: {"changed": 5, "initial": 1, "unchanged": 340}`. Pointer equality
is reported separately as a diagnostic. The mutated copies are tested in memory
without the file hash guard, so the fold and structure checks must reject them.

| Check | Observed receipt |
|---|---|
| Two complete archive rebuilds | Identical 189,747-byte candidates and identical custody receipts |
| Isolated reader snapshot, synthetic control | Exit 0, synthetic fold only |
| Isolated reader snapshot, missing candidate | Exit 1, file absent |
| Isolated reader snapshot, exact candidate and negative controls | Exit 0, 346 ordered matches and six rejections |
| Changed row or swapped source operands with record sequence retained | Callback 9 native row mismatch |
| Reversed source records, missing callback, duplicate callback or wrong domain | Rejected by record order, expected census, callback chronology or schema, respectively |
| Invalid compressed archive stand-in | Exit 1 on compressed identity, with no output directory created |

The isolated reader snapshot contained only the verifier and, for the
candidate-backed check, an explicit copy of the candidate. It had no
`.local-work/` tree, game, original archive or source receipts. The local
stand-in demonstrates the procedure after asset approval and availability.

## Local custody and rebuild

The loose historical session path was retired by the [archive migration](../../experiments/resources-evidence-consolidation/execution.md).
The actual owning `resources-production.tar.zst` matches the 351,425,006-byte
archive pin. The local builder hashes the compressed bytes before and after
reading, checks file identity and authenticates the embedded inventory. It reads
and hashes all 20 members of the C19 session and 25 historical run source-ledger
members, plus the embedded inventory. The session member set and digests agree
with the original seal. All 611,926 raw record digests, offsets and lengths match
the journal, and the original retirement receipt has zero active/failed calls.
The source census is scoped to C19 members in the owning archive. The reader
procedure above needs none of those original files.

```text
python -B research/evidence-access/d5be/c19-build.py .local-work/research-archives/resources-production-preparation01/resources-production.tar.zst .local-work/d5be/c19/rebuild-N
```

Use a fresh `rebuild-N` name under the ignored C19 staging root. The
[builder](../../../research/evidence-access/d5be/c19-build.py) uses installed
CPython 3.14.3 stdlib Zstandard/tar readers and the hash-matched project-owned
[070 record decoder](../../../runtime/beacon-resource-070/inspect_resources.py)
for individual record fields. It streams the owning archive read-only, uses the
tracked live-source ledger, and writes only the candidate and `custody.json`
in the explicit local output directory. It makes no raw copy and accesses no
target, configuration, save or analysis database. Identity, journal, scope,
population and census mismatches stop before candidate creation.

The candidate's input pointers, FormIDs, order and recorded row outputs for all
346 callbacks also match the authenticated historical `scientific-summary01.json`
through a one-to-one pointer alias mapping. The historical receipt lacks the
selector and record-sequence fields required for a complete fidelity check. A
separate direct binary reconciliation by the primary compares those fields and
the complete callback inputs and outputs against the raw WAL for the exact
candidate. Independent final review is recorded at the D5BE package level.
Both exact candidate rebuilds use the same source and method. The earlier local
probes rejected an overly narrow initialization FormID assumption and a phase
comparison that included initialization among preview runs. The final method
keeps initialization in the raw census and compares the six preview runs alone.
