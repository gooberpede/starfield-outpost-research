## Highest-value decisions

1. **Site and territory information (A12–A16).** For a Planner/importer, knowing
   planet identity is useful now. Knowing every biome crossed by a clipped build
   territory requires a common-frame connection between territory membership and
   biome boundaries. Exact continuous lon/lat is not automatically a prerequisite
   if a qualified native indexed-context query can answer the site question.
   First assess existing archived established-Workshop inputs; separately brief
   any missing discriminator. Do not substitute planet resource lists or one
   center biome for actual site coverage.
2. **Saved reconstruction (A02, A41, A46).** Exact active-player membership,
   hab wall selection and shared backing item quantities materially affect a
   faithful save import. Prioritize field-specific existing-data work before new
   live work. Exceptional historical Habs remain a different ownership question
   from the new wall-appearance screenshots.
3. **Realized behavior (A23, A29, A32, A48).** Conditional remote update and
   timing mechanisms already exist. If actual rates/freshness matter, obtain one
   identity- and invocation-matched state/entry/inventory sequence capable of
   distinguishing the alternatives. Repeating a visible nominal rate cannot
   establish actual output, remote residency or cache freshness.
4. **Public explanation (A52–A54).** Agree release scope and qualify stale global
   status and inaccessible evidence dependencies through the separate release
   program. These documentation/reproducibility defects can often be repaired
   without reopening science. No licence or publication classification changes
   are proposed as an automatic audit action.

## Inclusion, omissions and limits

This is a bounded coverage audit, not a line-by-line replication of every
experiment. Selection began with README, research state, backlog, subsystem map,
known-fact/hypothesis/state/function/decision registers and position capability
records. Report answer tables and current review dispositions were then checked
for **every named core workstream E1–E3, P1, S1–S2, C1–C3, CR1–CR3, R1,
L1–L3, DA1 and SD1–SD3**. Targeted supporting documents were read for the screen,
position, persistence and supersession questions. The source inventory records
paths/hashes and the nature of selection, not an assertion that every byte was
semantically reviewed.

Earlier coverage includes manual controls/output links/containment, historical
and donor corpora, active and alternate beacons, capacity/body/anchor/grid work,
membership/population corrections, native availability and region dependencies,
position observers, external-debugger abandonment, 0.8.0 scientific NO-GO and
synthetic spatial/x87/geometry qualifications. Unsuccessful or superseded tools
are retained as method history, not counted as missing gameplay experiments.
Local review receipts were consulted where they control later dispositions.

Excluded from fresh execution: raw save re-decoding, full native re-analysis,
installed override merging, game/Creation Kit operation, observer deployment,
full licence/history/privacy release audit, unrelated engine reverse engineering,
SD3 navigation/pagination, importer/mod implementation and any release action.
No new external source was consulted or incorporated. Links cite existing project
research and preserve its credited primary/source provenance. All remaining
negative statements mean unsupported in the named examined source set, never
universal nonexistence.

The six supplied images were inspected as appearance witnesses and hash-pinned.
Their filenames do not establish a build, chronological control, save pairing,
input event, internal object identity or load epoch. The four new Hab images
show four appearances, not proven exhaustive variant count or saved state.
Original accepted reports, registers, classifications and reviews were not edited.
