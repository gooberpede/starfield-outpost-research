## Material classes and testable decisions

| Material | B0 decision and testable example | Required later evidence |
|---|---|---|
| Original explanations, algorithms, diagrams and numeric analysis | Candidate: a project-authored build-budget explanation and numeric table. A CSV suffix alone does not establish authorship or rights. | Claim/source lineage, embedded-material and privacy review; B4. |
| Native addresses/offsets, identifiers and bounded in-document assembly/pseudocode | Candidate: the minimum excerpt needed to explain one mapped branch, with source/build/domain and commentary. A complete function dump pasted into Markdown does not become bounded by changing its extension. | Necessity, extent, origin and actual rights review per excerpt; no wholesale prohibition solely because assembly appears. |
| Project-authored helpers, build definitions, xEdit scripts | Source-first candidate: tracked `xedit/SOR_OutpostRecon.pas`; an installed identical copy adds no new content. Original analysis code reading a save is not game decompilation. | Exact author/version, rights and dependency review, reads/writes/prerequisites, synthetic example; B3. |
| Standalone game decompiled .c/.asm, bulk disassembly, analysis databases | Exclude: a whole native export or Ghidra database remains private even if useful for reproduction. | Document local extraction/recreation method and hashes; do not distribute input. |
| Game/tool installations and their files | Exclude: EXE/DLL/ESM/BA2, game-install INIs, extracted assets, installed Ghidra/xEdit/x64dbg and files from the Starfield installation. | Lawful independently obtained prerequisites and source hashes, not copied installations. |
| Game-derived dumps | Normally exclude: an ESM-wide record dump. Individually reviewed essential nonsensitive evidence may be proposed separately. | Exact claim necessity, minimized extent, rights/privacy and publication decision; no automatic dump exception. |
| First-party control saves | Candidate: exact selected Kreet Save37–39 originals from the CS input ledger, after policy integration and file-specific checks. No selection is made here. | Producer, lineage, original hash/bytes, account/service IDs, Windows paths/metadata and unrelated state review; character names acceptable. |
| First-party screenshots | Candidate: selected L3 rejection witness with uncertainty caption and exact hash. An image does not establish an exact reference/save join. | Practical pixel/metadata inspection for incidental personal material plus game-content rights review. |
| First-party mature saves | Selective candidate only if essential or unusually valuable: a unique crew/storage witness may justify review, not automatic full-corpus distribution. | Explain why minimal derivative/synthetic evidence is insufficient; scrutinize unrelated playthrough/mod/quest/account state. |
| Third-party saves | Exclude without specific redistribution permission: donor TDX1798 originals remain outside the release under SOR-P-0003. | Separate rights-holder permission and user acceptance of exact disclosure; consultation/local inspection is insufficient. |
| Logs, memory, captures, credentials and private correspondence | Keep protected/local: an original observer WAL is not a public build input. Credentials/private correspondence are excluded. | Prefer authored summaries; any proposed derivative requires later authorization, independent identity and privacy/rights review. |
| Synthetic examples and configuration | Candidate: an authored minimal fixture with invented paths. A real run lock renamed as a fixture remains private pending review. | Verify no embedded proprietary/private bytes; document what synthetic behavior proves and cannot prove. |

Examples identify existing families described by RR1's
[evidence ledger](../publication-readiness-rr1/evidence-candidates.md) and
[source ledger](../publication-readiness-rr1/source-and-reproducibility.md), not
fresh approvals. Original authored work keeps GPL-3.0-or-later. Facts/identifiers
are not newly owned because recorded here. Bethesda underlying material,
third-party saves, tools/dependencies and SFSE retain their separate boundaries.
Keep the exact approved SFSE header and MIT notice scope; do not infer runtime,
CommonLib or Address Library reuse. Confirm actual author/contributor notices.
Internal approval rules add no conditions to downstream GPL recipients.

## Source-first method closure

B3 selects source method by method: maintained source, exact scientifically
significant historical source, disposable helper, generated output, protected
original and external prerequisite have distinct dispositions. The approximately
15,008 ignored candidate occurrences are not a promotion list or unique programs.
RR1-010 and RR1-021 require resolving the exact historical hash from Git/frozen
sources or declaring its absence. Never relabel today's code with yesterday's
hash. A qualified current replacement needs its own evidence and limit statement.

For each selected claim record report/review, actual build coverage, method source
path/revision/hash, configuration, dependencies and effects, lawful external-input
route, minimal synthetic example and decisive evidence availability. Use RR1's
tiers: method reproducible without original evidence; method requires lawful
external inputs; method source incomplete; historical evidence only. Missing raw
evidence need not bar a supported claim, but its consequence must be explicit.
Prefer readers extracting from their own installed game over distributing dumps.
No automatic downloads, tool execution or live commands are enabled by the guide.

## Supplementary evidence contract (prospective)

B4 proposes an index reachable from the versioned Git repository/research release.
Each archive entry records asset name/versioned GitHub Release URL, archive bytes
and SHA-256, codec/tool/version and exact member manifest. Each member records
path/size/SHA-256, producer/provenance, original or derivative status, experiment
and claim references, rights/privacy decision/reviewer/date, publication class and
availability limits. Record transformations with original/output hashes, command,
tool version and reproducibility impact. Preserve original file bytes/hashes;
archive compression is packaging, not permission or semantic validation.

Use compressed supplementary assets normally hosted by the project's GitHub
Release and linked from its repository. Any alternative must still be reachable
there and separately approved; third-party file-sharing hosts are excluded.
Keep bulk binary evidence out of normal Git history by default. Verify archive
member hashes and versioned links in B6. Codec/splitting, files and URLs remain
unselected; no archive or asset is created in B0.

## Current guidance versus historical archive

B1 supplies current reader routes/status/successor links. Preserve dated findings,
failed approaches, offsets and old paths as historical provenance. Mark protected
local evidence explicitly unavailable in a fresh checkout and provide accessible
claim-specific summaries. A published relative link must resolve to its promised
document; a local-only payload label must not masquerade as a public download.
Missing external evidence is a stated limitation, not a broken-link repair that
silently invents evidence. B2 uses occurrence-specific corrections or disclosed
wrappers/derivatives for historical authored defects, preserving primary logs,
identifiers, hashes and actual historical verdicts.
