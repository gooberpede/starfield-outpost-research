# B0 publication policy and release scope

2026-10-21, Australia/Sydney. **Policy proposal; publication NOT CLEARED.**
The maintainer's [invoked B0 brief](../../implementation-briefs/CODEX_BRIEF_SOR_B0_publication_policy_release_scope.md)
settles the choices below for this record. It authorizes documentation and review,
not integration of policy exceptions or execution of later batches. Research
confidence, coverage, scientific completeness, publication eligibility and
permission to disclose remain independent. No historical finding is reclassified.

## Settled maintainer decisions

One coordinated research-archive release will join the approved public repository,
tagged research snapshot and selected GitHub-hosted supplementary evidence. Keep
development private until approval. This is an explanation and reproducibility
archive covering runtime and persistence, with useful scoped results and explicit
negative history; it is not a software product or exhaustive engine account.

Original authored work retains GPL-3.0-or-later; the grant does not license game
material, external dependencies or other people's saves. Source-first reproduction
is preferred. Original helpers, explanations, diagrams, locators and bounded
explanatory assembly/pseudocode are candidates for review. Standalone game
decompilation, bulk disassembly, tools/installations/databases and game files are
excluded. First-party control saves/screenshots are candidates after practical
rights/privacy review; character names are acceptable. Mature saves require
unusual value or necessity. Third-party saves require specific redistribution
permission. Preserve originals/hashes; selected binary evidence belongs in
compressed supplementary archives with manifests, normally GitHub Release assets,
not bulk Git history or third-party hosts. Cleanup is manifest-first and requires
separate subsequent deletion approval. Details and testable examples are in
[scope and evidence](scope-and-evidence-policy.md) and [retention](local-work-retention.md).

A research-release ID is independent of the Bethesda game-build ID. Every release
needs an accepted primary baseline manifest, historical-build exceptions and
per-finding applicability. Significant semantic identities join existing registers
to version-specific locators. Later updates receive proportionate reassessment,
not automatic rediscovery or release. [Versioned baselines](versioned-baselines.md)
defines the prospective schema and four qualification outcomes; it recovers no
new locator and makes no compatibility promise.

## Proposed single-release sequence (Codex recommendation)

1. B1 agrees the selected runtime/persistence claim/build matrix and reader routes;
   B2 corrects bounded authored prose. B3 closes selected method-source identity
   and prerequisites. B4 resolves exact rights/privacy/history choices and policy
   tensions. B5 addresses approved creator/housekeeping decisions separately.
2. Freeze a candidate tree/commit, proposed refs and reachable history, baseline
   manifest and exact asset inventory. Prepare reviewed hashes and versioned
   repository-to-asset links while still private, under later explicit authority.
   Any changed byte or ref invalidates the affected B6 review scope.
3. B6 independently checks that entire proposed surface and records required
   clearances, accepted exceptions and remaining limitations. Maintainer then
   explicitly approves exact contents, refs, visibility actions and timing.
4. Under that later authority, prepare the reviewed tag and draft release/assets
   privately, verify access and hashes, then coordinate visibility switch and
   release publication in the approved window. Verify public versioned links and
   downloads immediately. GitHub operations are separate, not atomic; no guarantee
   of zero visibility gap is made. Hold before visibility if any check fails.
5. If failure occurs after visibility, stop further disclosure, notify the
   maintainer, and use only their approved recovery plan. Unpublishing cannot
   retract downloads; never assume re-privatization erases exposure or rewrite
   history automatically. Record actual surface and outcome.

No step above executes in B0. Release preparation and rollback capabilities must
be verified in the later approved environment; no remote state is inspected here.

## Deferred maintainer choices

wording; release schedule, exact refs and recovery actions remain open. A similar
file's distribution elsewhere supplies no permission here.
