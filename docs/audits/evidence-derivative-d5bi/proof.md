## Custody and transformation

The local builder authenticates the exact 61,260,786-byte original ZIP, all
174 payloads in both retained custody forms, and the identical embedded seal.
The reviewed plan and 484 original source pins include the interpreter and
original observer identity. It runs the owned original core, scheduler, causal,
lifetime, geometry and counter validators. These check original frame lengths,
sequence, CRC, process identity, ACK and terminal accounting, and native bridge
accounting as applicable. The D5AP history index replaces only the original
causal reader's pair-enrichment callback. D5AJ separately recomputes source,
generation, owner and lifetime attribution from complete decoded originals.

Each projected journal has one schema/field-order/channel/process header and
one ASCII JSON array per original record. The line number after the header is
the original channel sequence. Core retains every scalar and signed request.
The six source birth slices contain geographic key operands and the constructor
token. Other source object bytes are withheld. Descriptor byte 0 and bytes
4–43 are copied. Bytes 1–3 become a first-seen equality class within this
process, preserving comparisons without publishing opaque padding. Nonbirth
source bytes must be zero in the original. Other wire framing and reserved bytes
stay upstream. Causal and scheduler retain every decoded operand including
full typed key, discriminator and queue copies where present. Lifetime
retains every decoded pair, original numbering, cursor and type identity.

Geometry retains the completed scan header fields and lifetime marks, all 36
occupied source/holder identities and their census counts, plus target resource
and nested allocation/count fields. Full decoded geometry validates shape and
extent locally. The verifier recalculates 3 resources, 78 regions and 180 points
for the target, validates target allocation shape and checks allocation/mark
relationships. Region headers, points, opaque holder words, consumer query
payload and other holders' nested shapes remain original-only. The projected
claim concerns retained allocation/content boundaries and counts.

The session projection copies process identity, a terminal operand allowlist,
and the lifetime coverage mark. Archive, seal, raw input member hashes, plan,
observer, build and protected sample pins bind the provenance. Original guard
bytes, protected-save custody, live operator actions, full ACK ledgers and
all original native receiver/ABI coverage remain upstream. The replay compares
the recorded loss/accounting operands and validates the projected record census.

## Rebuild

On the original offline machine, with the authenticated N2 source closure
available, use the pinned CPython 3.14.3 executable with SHA-256
`cce21c0e8710e304273e98ac4b2b0f5aceb639acbcd2343cbaa5c4e81619c45b`.

```powershell
python -E -B research/resource-retained-population/d5bi_build.py .local-work/d5bi/NEW
```

The output path must be new and free of reparse points. The builder checks both
caller-available disk floors, uses sorted members, a fixed ZIP timestamp and
mode, and deflates at level 9. It creates the ZIP, manifest and local
reconciliation receipt after the in-memory semantic replay. Rebuild comparison
uses exact ZIP, member and manifest bytes on the pinned environment.
