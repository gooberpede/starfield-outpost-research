# Proposed reader architecture

The top-level README should offer three direct routes. Its subsystem route leads to short guides that answer ordinary player questions first. The technical route organizes stable mechanisms, schemas, source pins and access tiers. The history route retains original results, supersessions, failed experiments and review records.

```text
README.md                           Choose a reader task
docs/
  guides/README.md                  Subsystem map and starting questions
  guides/<subsystem>.md             Explanation, persisted state, limits
  reference/README.md               Find technical contracts and evidence tiers
  reference/<subsystem>.md          Stable identifiers, predicates, sources, tests
  history/README.md                 Chronology and superseded interpretations
  research-roadmap.md               Crosswalk during transition
  research-history.md               Preserve supersession and old interpretation
  experiments/                      Original reports, data, reviews and evidence index
  implementation-briefs/            Brief index, loose controls and two proposed ZIPs
  audits/                           Review packages, audit index and administrative ZIP
  position-model/                   Preserve existing deep reference paths
  function-register.md              Stable function identities
  state-register.md                 Stable ownership and persistence identities
  PROVENANCE.md                     Exact source and build context
  SOURCES.md                        Attribution and provenance
  PUBLICATION.md                    Scope and evidence access policy
research/                           Authored methods and their effect contracts
save-analysis/                      Save tools, inputs and output boundaries
```

Use each guide to distinguish the gameplay question, runtime mechanism, saved representation, restoration authority and untested cases. Technical pages link directly to supporting rows and review. Each result needs its exact scope and evidence tier in the link caption. The report/review paths below remain stable through the proposed first migration. The [B1 scope matrix](../publication-readiness-b1/claim-build-matrix.md) and [roadmap](../../research-roadmap.md) supply the per-domain review and pin crosswalk. ## Reader journey tests

**Resource generation.** From the root, reach the guide in two clicks and explain how qualified reconstruction can yield equal or different complete source geometry. Identify the first eligible protected map miss, the conditional nature of GC-35–37, and the separation of saved descriptors, PCM and placed producers from transient contours. Follow the technical page to [D5AS](../../experiments/resource-retained-population/d5as-series-closeout.md#frozen-roster-and-comparisons). The result is two mask-0-reference and 28 mask-3-reference matches across 30 qualified starts under the operator-reported Save52 visit procedure. Per-start loaded save, full effective inputs, generating mask and cause remain unverified. Reproduce the advertised tier from a clean checkout. For example, recalculate mask shares for one named cohort from its tracked counts in the [D5AT ranking rows](../../experiments/resource-retained-population/d5at/active-rankings.csv), or check a rights-cleared per-run canonical-body comparison. The conditional mask survey supplies no actual winner probabilities. Challenge by following [D5AU's scope change](../../experiments/resource-retained-population/d5au-gap-closure-decisions.md), [D5AS's excluded attempt](../../experiments/resource-retained-population/d5as-series-closeout.md#acquisition-and-exclusions) and the [D5AK equal rebuild counterexample](../../experiments/resource-retained-population/d5ak-a-report.md). Mark the historical observation held if the durable derivative is unavailable.

**Power.** Find the distinction between saved allocation and effective post-load graph within two clicks. Recompute only the published static ordering logic or verify Save29's allocation using its approved original and the exact documented reader. Find the historical repeated-load caveat, ordinary Save29 adjudication and writer NO-GO without opening a private trace.

**Identity.** Locate ordinary owner evidence and explain how it differs from registered UI results. Verify a named saved join only with the relevant approved witness and reader. Follow the supported-root and retained-assembly counterexamples to challenge any exhaustive active census claim.

For each journey, require a direct guide to reference link, one direct evidence/review link from each selected technical claim, and one history/supersession path to the corresponding older finding. Pass when an independent reader can state the result, build, access tier and one decisive limit and can run or inspect the advertised evidence route without local working material. Final measurements belong to the guide/migration brief.
