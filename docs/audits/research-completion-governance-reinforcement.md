## Enforcement, independence and limits

The procedure enforces closure through required reviewer inputs and explicit
reject/escalate decisions. No tool blocks an agent from writing an inaccurate
completion claim, and there is no automatic orchestration or scientific oracle.
Literal structure checks can detect missing fields/references; they cannot prove
branch completeness, active maintenance or blocker necessity. The independent
adversarial application must challenge those facts. If separate contexts are
unavailable, use the existing manual two-pass handoff; record NOT REVIEWED and
withhold accepted closure for this frozen contract until mandatory review occurs.
This capability limit requires no new tool or permission in this session because
separate reviewer contexts are available and explicitly authorized by this brief.

policy edits. Baseline receipt pins actual HEAD/index/status and original brief.
Existing CPython and Git only; no new dependency or third-party material. The
first preparation command failed at the WindowsApps Python alias; it wrote no
receipt or policy. The corrected command uses the installed CPython absolute path.
Subsequent diagnostics/iterations and actual reviewer returns are retained
under `.local-work/governance-reinforcement/`; none are summarized into a false PASS.
