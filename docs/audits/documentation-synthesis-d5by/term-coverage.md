# Terminology and notation coverage

The authoritative [technical glossary](../../reference/glossary.md) predates
D5BY. Its existing definitions cover geography, source lifetime, ownership,
construction, resource availability, production, storage, cargo, UI, defenses,
electrical state, address domains and evidence language. The glossary stays
at its existing path and retains earlier anchors.

| Prior resource | Scope and overlap | D5BY treatment |
| --- | --- | --- |
| Glossary and earlier D5AY glossary amendment | Canonical meanings and contextual aliases for the resource pilot, extended by later guides. | Extend the canonical page with input, reference and time domains and confidence/access language. |
| B2 notation and native export-ID guide | Preferred VA, RVA, member/vtable displacement, masks, file offsets and local export numbers. | Carry portable definitions into the existing glossary. Keep original receipt labels in their experiment namespace. |
| Evidence standard and state register | Confidence, basis, state classification and stable locators. | Link the standard and register. Keep static, saved, observed, derived and controlled-execution meanings distinct. |
| Position model, resource coordinate contract, geometry schema | Exact frames, record types and comparisons. | Keep formulae and schemas with their subject. Glossary covers frame, raster mask, geographic source, deposit and canonical body. |
| RC1 declarations and capability conventions | PEX signatures, native declaration meanings and per-surface status. | Glossary defines the domains. The access reference keeps the exact signature and action route. |
| Guide-specific examples | Producer row and reason, powered bit, inventory stack, display slot, assigned actors, and UI epochs. | Keep definition or canonical glossary link beside the term. The technical reference gives precise fields and consumers. |

New explicit entries cover N244/H?, ESM/BA2/PEX, Papyrus VM, tagged saved
RefID, epoch, vtable byte offsets, bit masks, nominal/effective, the project
confidence and evidence terms, native fixtures, historical and held statuses,
local qualification and clearance. Existing entries distinguish source from
deposit, retained from rebuilt, and saved representation from realized state.

The [identifier index](../../history/research-identifiers.md) carries study
labels. The [claim lookup](../../history/claims.md), [route lookup](../../history/evidence-routes.md)
and [save aliases](../../history/save-identifiers.md) give literal IDs. Bare
A1/B2/C1/R3 require source context. Local export sequences, absolute paths,
and case-specific symbols stay in original records. Familiar gameplay words
and source-specific locals without a cross-subsystem meaning are intentionally
left to their immediate context.

The [citation census](identifier-census.csv) records every matched identifier
in the bounded guide/reference, roadmap, current documentation index and
selected claim/route pages. The [census source](citations.py) prints the
resolved lookup or the explicit context and fails on any unclassified match.
Full claim, route and selected joins are checked separately against the
pinned proposal and overlay. The pattern is bounded to project research
families and sample IDs. Function or record symbols outside those families
retain their cited local registers.
