# Completion drain and first-miss specification

The missing observation is a **native completion-to-eligibility join**. From
one rectangle admission, track the actual completion packet, server and
task lifetime through consumption and the resulting dependency changes.
Then show that the real ready-file density branch reaches native worker
publication while the actual tag-1 layer preparation remains pending on
ContentManager. A receipt for the committed preparation fixture alone
would stop short of that observation.

All native addresses below are preferred static VAs for Starfield
**1.16.244.0**, image base `0x140000000`. Runtime pointers are meaningful
only within a single allocation lifetime and process. Keep the native
task key, original signed Int2, owner FormID, source key, source allocation,
visited token and full-pointer map key separate.

## What the fixture omits and what to observe

The committed preparation fixture records a deliberately shortened path. Its post-receiver shim at `0x1428d8a4e` leaves through the pump epilogue and skips normal progress. Its layer producer takes a private cut from `0x1407b4d08` to `0x1407b513a` after publication, bypassing the original neighbor and layer tail. It then invokes the emitted registration callback directly. A state-25 tag-1 packet produced at those boundaries supplies a bounded admission observation if executed. It cannot by itself demonstrate the full native preparation dependency or density eligibility. The older state-25 control used a supplied second command. Neither final cut has a source-matched execution receipt.

For the normal cold coordinate, D5S-F1407b4bb0 first publishes the
preparation node, then retains its handle while resolving the four density
neighbors in native order `(-1,+1)`, `(-1,0)`, `(0,+1)`, `(+1,+1)`.
It acquires the density handles at `0x1407a1260` and can recursively
acquire in-bounds coordinate handles. D5AE-N082/N083 locate the final
layer work constructed via `0x1407b55b0 → 0x1407b58a0`. The
pending branch registers a state-zero node, adds the prerequisite
handles via `0x140362140` and submits the commit via `0x140362300`.
Their callsites `0x1407b570b` and `0x1407b5726` are distinct from the
first preparation publication. Identify the actual live handle edges and
coordinate/final wait transitions. The layer must still await its own
preparation at the density boundary. Its waiting does not itself impose
an edge on a ready-file density neighbor.

In the paired **hold/drain control**, hold the original rectangle
NotifyComplete command before the matching server receives it. Confirm the
selected rectangle remains live, its reader is still owned and its dependent
coordinate work remains gated by that completion. Service the correct
command on the matching ProcGen receiver with ContentManager still at its
released-receiver boundary. Require native completion, destruction and key
erasure for that lifetime. Join any emitted target page to removal of the
selected category-zero edge, the appropriate count/evaluator change and the
admitted coordinate continuation. Confirm actual layer-preparation
publication and its outstanding edge on downstream layer work. Then require
native ready-file density publication and claim on the shared started pool.
Withhold a real density prerequisite in a separate contrast and verify no
equivalent early publication. Allow normal ContentManager progress in the
layer contrast and confirm consumption of the same layer-preparation
command and satisfaction of its edge. Layer dispatch then depends on its
remaining prerequisites. A queue snapshot or state 25 alone proves neither
eligibility nor exclusion of the layer rival.

In the selected-source lookup control, a cold map and a foreign-pointer
