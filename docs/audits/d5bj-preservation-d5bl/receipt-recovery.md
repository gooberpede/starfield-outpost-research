## Distinguishing candidates from receipts

- The isolated preparation stdout is byte-identical to run 06. This binds
  the matching payload to the older scope. The empty stderr and an exit zero
  are evidence for that invocation. A copy or echo of the same JSON supplies
  no separate execution.
- Run 07 has its own stdout and empty stderr. The retained outer command
  reports the child exit separately and the output records the receiver
  returning at `0x1428d8a4e`, with running state 9. The wrapper ran before
  the last edit to both files and emitted no contemporaneous method hash.
  The reconstructed intermediate source explains the additional field.
  Both 06 and 07 used fixture-supplied per-cell callbacks and a supplied
  pending layer. Their success ends at the observed publication boundary.
- The exact-final hash strings occur in inventories, the prior prose and
  patches carrying that prose. The final marker occurs in source, edits and
  discussion. Neither kind of hit is a source-bound command and output.
  The last visible completed command inspected retained static evidence.
  The later visible edits are source changes. The service error supplies
  no post-edit command exit and no operation-specific restriction.
- The older checker joins existing JSON from separate controls. Its output
  and adversarial refusals authenticate that earlier data-level behavior.
  The current checker additionally requires the observed receiver VA and
  native layer-producer marker. Run 07 supplies only the receiver VA. A
  matching expected route label, mask or hash string cannot fill the missing
  producer and checker invocations.
