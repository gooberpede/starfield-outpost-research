## 1. Research purpose and scope

This project concerns *outpost resource behaviour experienced by a player*, not generic caching, optimization or exhaustive engine archaeology. Explain when an already-generated **outpost-related geographic resource population** remains in use between ordinary actions, when it is retired/erased and then reconstructed, and why two visits may appear to have identical deposits despite a new generator execution. Tie conclusions as far as evidence permits to **specific player actions and qualified native predicates**, not only to abstract native functions.

The established foundation must remain intact:

- D5AH maps distinct Grid/source, ProcGen pointer-map holder, nested geometry-collection and visited-token lifetimes. Map hits and visited bypasses are different; retirement can erase a holder while leaving a visited token; a true broad reset can clear both. Same geographic key, equal pointer values or equal geometry do not prove uninterrupted ownership.
- D5AK Episode A directly observes an **ordinary Feynman V → Lodge exterior fast-travel marker → Feynman V** journey: an installer/true reset, owning Grid clear, target map erasure, old holder and content lifetime endings, new source birth and generation on return. Two different original queries, `[8,3]` and `[-1,11]`, each sampled mask `0x3`; complete geometry was identical. This establishes **reconstructed-identical**, not retention, for that specific episode. It does not establish the precise initiating travel caller or a universal Lodge-trip rule.
- D5AS establishes two independently qualified complete Feynman V geometry classes under 30 fresh-process observations (2 mask-0-reference, 28 mask-3-reference, none other); it does **not** record within-session changed geometry or a direct sampled mask for each snapshot. D5AT provides conditional new-site inputs, not real visit cohorts or probability distributions.
- D5AU disposed of legacy GC-06/10/24/31/33/34 within amended scope and added GC-35–37 as explicitly new, OPEN questions. **Do not reopen retired scheduling, general travel-ingress chronology, Workshop first-refresh ordering, terrain-readiness correlation or extractor-output experiments** as implicit dependencies.

**Primary deliverable:** an **outpost player-action persistence matrix** distinguishing (i) confirmed retained population/reuse, (ii) confirmed destroyed and reconstructed identical, (iii) confirmed destroyed and reconstructed different, (iv) reconstructed but output unqualified, (v) conditional native prediction, and (vi) unknown/blocked. A row must never imply a universal gameplay rule from a single episode.

## 2. Frozen controlling questions and successful-answer standard

### D5AV-Q1 — GC-35: Which ordinary outpost actions preserve resident populations?

For a bounded set of representative player actions, identify whether they can preserve the **same complete geographic source population** and through which native predicate/owner route. Distinguish true pointer-map hit, consumer reading a still-retained map entry, visited-token bypass, density/layer aggregate bypass and cached Workshop list. Specify the observable evidence needed to establish uninterrupted source, holder and collection ownership; do not infer it from unchanged contours or token equality.

**COMPLETE** when the player-action matrix distinguishes positively established retention/reuse from conditional retention paths and unknown actions, with primary source/lifetime evidence for each claimed case. A proven scoped native rule is acceptable without a new retail observation; explicitly label whether its action mapping is static/conditional or retail-confirmed. A universal statement that every ordinary warm return retains the source is **not required and must not be claimed**.

### D5AV-Q2 — GC-36: Which ordinary actions invalidate and reconstruct?

For the same bounded actions, map applicable source retirement, owner/Grid clear, manager/ProcGen reset, pointer-map erase, visited-state handling and subsequent demand/eligible construction. Reconcile the action-specific D5AK Episode A path and any other already-observed paths; separate an action *permitting* reset from evidence it *executed* reset. Include the possible **retired-source / surviving-visited-token** state in which returning demand can bypass fresh construction despite absent map geometry.

**COMPLETE** when the matrix gives qualified predicates and existing runtime witnesses for destructive transitions, subsequent generation versus no generation, and the action-level limits. Do not demand complete discovery of unrelated reset callers, optimization policy or every worldspace; do not declare a route universal without positive applicable evidence.

### D5AV-Q3 — GC-37: When can a player encounter a new geometry outcome on return or load, and what survives?

Explain the distinction between **same source still retained**, **new construction with equal complete output**, and **new construction with different complete output**. Address save-without-load, ordinary in-process load, new-process load, same-planet travel, another-planet/system return and D5AK's exterior Lodge return, distinguishing read-only native findings from observed episodes. Explain what standard Save52 serialization retains (descriptors/PCM/placement and relevant objects) versus what has **not** been established as saved (live pointer-map holders/full generated contours), using the bounded D5AD/D5AH save investigations; avoid broad independent save archaeology.

**COMPLETE** when a defensible conditional account explains the *appearance* of persistence and the circumstances required for a fresh raster-sampling opportunity, with precise limits on whether fresh construction actually occurs and whether geometry changes. No fresh within-session changed-geometry retail observation is mandatory if the answer is explicitly conditional and the existing runtime/native evidence suffices; do not invent such an observation.

Investigate the following at the **same established outpost/source whenever evidence permits**; prioritize D5AK Feynman V for evidence continuity. Combine actions with identical proven native effects rather than manufacturing redundant tests. Additional actions only when positively required to answer the frozen questions.

| Player action | Principal discriminator |
|---|---|
| Remain in the outpost; ordinary movement within retained coverage | Stable owner/source/holder, no true reset/erase; distinguish lack of new demand from actual cache reuse |

| Save while outpost remains loaded, without reloading | Separate writing save data from live population lifetime; no automatic reset inferred |
| Reload in the same running process | Confirm known loader/revert/reset predicates; distinguish conditional preparation from an observed actual target reconstruction |
| Exit game; restart and load the same unchanged Save52 | New runtime owner/source/holder; fresh construction opportunity where eligible; D5AS observational distribution and limitations |

For every row record: player action and exact context; evidence provenance (STATIC/SAVE/NATIVE CONTROL/RETAIL); qualified owner/component/Grid/ProcGen predicate; source allocation and geographic identity; holder/collection lifetime; visited state; pointer-map hit/miss; actual raster sample/generation evidence or lack thereof; complete geometry equivalence where measured; player-facing consequence; confidence, scope and missing decisive edge.
