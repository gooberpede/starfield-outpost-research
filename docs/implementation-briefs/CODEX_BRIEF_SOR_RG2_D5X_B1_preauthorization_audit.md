## 3. Mandatory B1 evidence acceptance matrix

Create an explicit per-boundary matrix keyed to the **fourteen native sites** in `d5x-schema.md`: 0 provider entry, 1 selected cursor, 2 visited decision, 3 source-map lookup, 4 converter scope, 5 generator scope, 6 ordinary sampler, 7–11 five lifecycle invalidators, 12 protected reset unlock, 13 actual normalizer consumption. For each site the matrix must specify the precise native execution condition, expected event kind/operands, how event identity and counter/absence are validated, reader output, semantic prerequisite, and what remains untested if the site is not reached.

For postflight, require a site-by-site **observed coverage report** distinguishing at least:

- installed/guard-verified vs not installed;
- **native execution positively witnessed** vs **not observed** (never infer zero native executions from zero admitted events);
- event admitted/authenticated vs lost/unacknowledged/ambiguous;
- relevant invocation/source/frame/epoch correlation valid vs invalid/untested;
- expected branch not exercised vs branch exercised but instrumentation failed;
- positive witnessed complete chain vs partial diagnostic or explicit contradiction.

Do not invent per-site execution counters if they are absent. First inspect the actual available records, hook metadata and reader reductions. Where the schema cannot distinguish an unexercised branch from lost coverage, mark **INDETERMINATE** and identify the minimal defensible diagnostic change. A missing reset or legitimate visited/map hit must not be classified as a failed cold first-construction witness or a healthy sampler malfunction without relevant earlier boundary evidence.

**Proposed B1 grading** (audit and refine against the actual data, then freeze before any retail approval):

1. **Startup-only / partial:** exact DLL and all 14 sites READY, fresh challenge ACK and healthy capture, but no authenticated native boundary activity. This is *not* full B1 success.
2. **Partial native coverage:** authenticated native provider/selection or other real boundary events, but insufficient relevant path to verify the entire construction-winner observation mechanism. Report exactly which sites were exercised and which were unavailable/uncertain; this does *not* authorize B2.
3. **Full B1 instrumentation PASS:** genuine retail provider, cursor selection and the relevant downstream native decision/descriptor/generator/sample boundaries are positively authenticated and correlated on a valid execution path, with required lifetime/coverage integrity. An actually witnessed cold first-construction chain is **not required** for B1, but if any required path is not naturally reached, do not fabricate its validation: report partial and seek a separate scoped decision. Lifecycle/reset sites may be unexercised when no reset occurs; installation guarding plus disposable proof must remain separate from retail exercised coverage.
4. **Engineering failure / uncertainty:** incorrect identity, hook integrity failure, uncorrelatable exercised boundary, invalid transport, unresolved admission failure or missing safety protection. Keep operational completion, protection outcome, native coverage and scientific conclusion separate.

Full B1 need not make a B2 scientific claim; it must establish the native observation capability needed for B2 rather than simply READY. A postflight that produces thousands of authenticated but scientifically uninformative records must explicitly say *where and why* correlation stopped.
