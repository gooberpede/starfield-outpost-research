## 1. Purpose and completion contract

The scientific objective is to reproduce **the engine-native durable position of an ordinary player-built outpost**, starting with persisted save data and relevant installed native/game definitions, rather than merely predicting a position from correlated metadata. The primary target is the **body/frame/grid/subcell and durable workshop-center representation actually used by the engine**, not a speculative continuous geographical latitude/longitude for the beacon. Keep the distinction among the current physical beacon, the original compensated workshop center, the saved planetary site anchor, and the native selected terrain frame.

The previous external-debugger event-oracle method is **closed** after demonstrated unsafe replay/retirement behavior. Do not revive it, run its binaries/cards, or allocate this assignment to making it safe. The partial success of the passive SFSE observer and the existing static/save findings remain legitimate evidence, not a native end-to-end oracle for the entire transformation.

**Required final product:** a documented, runnable deterministic position reproducer, a branch/dependency account tied to exact native provenance, regression coverage over the supported corpus, and an independently reviewed scientific disposition that states precisely which algorithm stages are validated, inferred or unvalidated. The goal is complete, independently validated reproduction **where the evidence and authorized methods permit it**; the implementer must not falsely claim oracle equivalence from self-consistency. A finished negative finding about a particular algorithmic hypothesis is valuable, but a failed attempt to acquire an oracle is **not** completion of the whole reconstruction assignment.

### Frozen acceptance criteria

1. **Baseline preservation and inventory:** establish the committed current model/tests/predictions and their hashes; preserve prior archive, original saves, reader, observer, experimental records and frozen expected values unchanged. Identify the executable/version and code provenance for each native claim.
2. **Explicit input-to-output model:** implement or materially refine a standalone deterministic transformation from saved inputs to a precisely typed position representation, including selected body/site/frame, discrete grid cell, subcell residual and compensated workshop center as applicable. Where a stage is genuinely unknown, expose it as unknown—not a guessed default or silently substituted calculation. Document native arithmetic order, `float32` versus integer conversion, rounding, origins, hemisphere cases, branch conditions and error states to the extent supported.
3. **Branch/dependency resolution:** revisit the known relevant static chains and recovered evidence and pursue remaining plausible position-selection/translation dependencies to a defensible resolution. Do not abandon a lead merely because the first reference is indirect, a native value is ephemeral or one experiment cannot be run. Maintain a dependency/branch ledger with direct source addresses and an evidence classification.
4. **Independent validation:** use previously collected native observations and independent reference cases for which the same operation and input domain can be demonstrated; compare at bit-exact precision where justified and report every discrepancy without retuning frozen predictions. Build positive, negative, branch-boundary and holdout checks from the controlled and mature saves, clearly separating actual external expectations from expectations generated by the reproducer itself.
5. **Executable tests and evidence:** provide a repeatable CLI or module, fixtures/test harness, commands, provenance manifests and a result matrix for each supported case. Run the existing appropriate tests and investigate every in-scope failure; no passing subset may be presented as complete if a frozen mandatory test fails.
6. **Scientific coverage/disposition:** supply a stage-by-stage acceptance matrix distinguishing `NATIVE-VALIDATED`, `INDEPENDENTLY-CORROBORATED`, `STATICALLY-RECOVERED`, `MODEL-PREDICTED` and `UNKNOWN`, with specific grounds, counterexamples and scope. A method-specific negative finding must not be presented as falsification of the model or completion of other unresolved stages.
7. **Independent reviewer:** obtain an independent completion review against this original contract and primary repository evidence, resolve `REWORK` within this same assignment, and preserve the reviewer ledger. No implementer self-approval.

**Completion is not measured by an arbitrary number of save cases, functions examined, passing reruns or time spent.** Coverage must exercise the relevant algorithm branches. If genuinely unavailable independent runtime outputs make exact equivalence impossible within authorized means, exhaust and document safe, concrete alternative sources; present a strictly scoped negative/feasibility conclusion for the blocked stage and seek reviewer scrutiny. Do not relabel a plausible partial model `COMPLETE — PASS` for native equivalence. Escalate only a real authority/safety dependency or a reviewer-supported terminal feasibility decision, under standing protocol.

## 3. Investigation sequence and proportional verification

### A — Reconstruct what can already be proved offline

Audit the current transformation end to end against persisted bytes, native static code and independently established site/body identity. Trace the producer and consumer of each relevant output stage, including actual integer/floating conversion boundaries, 2x2 terrain footprints, rotation/reflection, site-relative versus body/world frames, and selected-origin/rebase conditions where necessary. Resolve contradictions; keep true alternatives explicit instead of averaging models. Implement reproducible diagnostics and small experiments as needed using existing artifacts.

Where an independent known position exists (controlled beacon placement, changed beacon position with fixed durable center, fixed ESM city/POI data), qualify **why** it is an oracle for the same operation before comparing. A city's saved site-anchor match does not prove its workshop center used the ordinary outpost creation path. Validate no broader than the underlying call path permits.

### B — Address missing native independence economically

Before building instrumentation, inventory native outputs **already archived** and cheaper alternatives (static dataflow, ESM/native-defined reference values, cross-save invariant, preexisting passive observer evidence, read-only save observations). If a remaining stage truly requires observing a live native operation, produce a **specific evidence-gap and minimal acquisition design**, including natural event/callback, ownership/thread context, read/output independence, viability, hazards and comparative validation value. A narrowly scoped **in-process SFSE observer** can be considered as a design alternative, but **no new hook, debugger, injected call, deployed DLL, live game launch, Vortex action or runtime acquisition is authorized in this assignment**. Do not turn an instrumentation proposal into the principal deliverable. Present any needed live approval as a distinct narrow decision rather than silently treating unavailable runtime evidence as obtained.

### C — Complete the runnable model and test it

Deliver deterministic implementation, frozen regression comparisons, boundary/pathological tests and an executable verification command. Address all discovered in-scope bugs before final submission. Distinguish calculated local coordinates from representations the engine actually stores/consumes; preserve raw float bits, FormID/ref identity and saved-input provenance in reports. Do not modify protected saves, mutable predictions, archived raw observations or native baselines to improve agreement. Every disagreement is evidence to investigate.
