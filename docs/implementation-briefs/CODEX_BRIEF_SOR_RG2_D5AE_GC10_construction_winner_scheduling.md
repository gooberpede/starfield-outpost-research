## Purpose, parent and frozen controlling questions

**D5AE-CQ / GC-10:** **When multiple eligible ordinary resource-generation requests can process the same geographic resource source, what determines which request actually obtains construction authority first under normal retail readiness and scheduling conditions—and how predictable is that winner?** Establish an integrated account of *eligibility → registration/dependencies → readiness → worker claim/execution → visited check → protected source-map decision → generator/sample*. Do not substitute a list of possible interleavings, an isolated winner example or a simulated scheduler for an explanation of the native scheduling process.

Freeze these four questions and their completion standards:

- **D5AE-Q1 — Eligibility and initial readiness.** Establish the exact predicates by which competing requests become eligible for resource construction, including world/descriptor/owner context, geographic source/Grid, definitions, raster availability, task registration/dependencies, and any deferred initialization. Explicitly test the upstream **D5AD GC-02/04/05** handoff: *could unfinished initialization change the set, eligibility or outcome of competing requests?* Identify native barriers, waits, failures and missing-prerequisite branches. **COMPLETE** requires proving the pertinent ready-before-use relationships or establishing a real overlapping-readiness mechanism and its effect, not an assumption that loading completed because the player was in the Lodge.
- **D5AE-Q2 — Real native scheduler.** Follow material ordinary paths from focus/region demand and layer/density task registration through dependency resolution, enqueue/publish, worker claim/dequeue, execution, and entry into the source provider. Identify effective ordering, queue disciplines, priorities, thread/task ownership, synchronization and conditional bypasses. Include **GC-06** fast-travel-to-demand ingress where it can affect eligible request creation/timing. **COMPLETE** requires a causal producer-to-consumer model that explains what is ordered by code and what is left to runtime interleaving; a merely enumerated set of scheduling possibilities is insufficient.
- **D5AE-Q3 — Construction authority and observed competition.** Determine exactly how eligible requests traverse the visited-list gate and source-map exclusive interval, and what grants the first *constructing miss* authority, including concurrent already-passed visited checks, hits, failures, missing prerequisites, resets, source retirement/reuse, and aggregate-reuse bypass. Explain B2's same-target contest, **`[4,-1]` invocation 3837** versus **`[5,0]` invocation 3844**, from their actual native operands/timestamps and lock/map outcomes, without inventing unobserved OS scheduling times. **COMPLETE** requires a model accounting for the actual observed winner and relevant counterexamples, not merely saying 'the second worker ran faster'.
- **D5AE-Q4 — Normal-play predictability.** Determine whether, under explicitly defined ordinary gameplay initial conditions, a first constructing request/mask can be predicted from stable ordering or whether native scheduling genuinely permits timing-sensitive alternatives. Distinguish **possible**, **favoured by a proven rule**, **observed once**, **normally selected**, and **empirically frequent**. Examine existing D5S/D5W and B1/B2 evidence and independent controls. **COMPLETE** requires an evidence-supported predictive contract or an adequately controlled negative showing which required winner-determining variables remain genuinely unconstrained, with specific consequences and a minimal discriminatory retail test if frequency cannot be determined offline. Do **not** claim observed retail frequency from one B2 session; **GC-31** remains separately concerned with repeatability across independent episodes.
