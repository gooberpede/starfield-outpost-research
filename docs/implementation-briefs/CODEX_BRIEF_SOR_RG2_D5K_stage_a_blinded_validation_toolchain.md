# Codex implementation brief — RG2-D5K Stage A
## Generic blinded new-outpost resource validation toolchain

**Authority:** Offline implementation, synthetic qualification, historical-control rehearsal and documentation only. **No new outpost creation, Starfield launch/attachment, save editing, retail acquisition, publication, staging, commit or push.** Future experiment Stage B requires a separately reviewed run card and explicit maintainer GO.

**Primary scientific objective:** Construct and freeze a reusable, technically enforced **location → prediction → sealed prediction → independent revelation → comparison** workflow for previously untested outposts. Candidate planets: **Kreet, Vectera and Jemison**. The actual planet/site is not selected using its resources. The experiment must remain useful when predictions are wrong.

**Critical acceptance rule:** **Prediction accuracy, agreement with native resources, exact geometry-match rates and any positive/negative scientific outcome SHALL NOT be acceptance criteria for Stage A or for procedural acceptance of Stage B.** Evaluate **independence, consistency, generalizability, reusability, deterministic reproduction, evidence integrity, coverage disclosure and truthful discrepancy reporting**. The comparator must report disagreement faithfully; an unexpected mismatch is a scientific result, not an engineering failure or a reason to tune the model, discard the case or retry with modified code. Distinguish technical failure to acquire admissible ground truth from a valid mismatch after qualified acquisition.

## Stage A task and design requirements

1. **Define the blind trial contract before implementation.** Specify roles and ownership of a newly created save: *location custodian* alone may read the raw save before freeze; *prediction worker* may read only strictly filtered location transfer, installed definitions and frozen approved algorithms; *revelation custodian* retains resource-bearing evidence, not released until an accepted prediction freeze; *comparator* reads sealed prediction and independently authenticated revealed results. Codex's prior exposure to known historical cases is not a substitute for physical isolation. Use separate work directories and actual access boundaries appropriate to the Windows environment (e.g. separate access-restricted processes/accounts, provisioned inputs or sealed bundles); demonstrate that the predictor cannot open or enumerate original saves, extractor tables, native resource captures, hidden custodian logs or revelation products. If same-agent role switching cannot guarantee nonaccess, specify and test an operator-mediated boundary with truly isolated runner contexts rather than call it a Chinese Wall.

2. **Location-only transfer schema.** Create a minimal versioned allowlist: observed installed body identity, exact saved beacon/Workshop identifier and native position operands, necessary frame/chart/geographic conversion metadata and placement radius/orientation only when independently evidenced. Do not include resource FormIDs, extractor/production rows, generated source regions, sampled masks, descriptor winner or any inferred resource fields. Validate fields, numeric encoding (retain native binary representations where necessary), source provenance, exact Workshop uniqueness, coordinate transforms and absent/ambiguous operands. A successful save parse does not prove that the emitted coordinate is the engine's effective Workshop centre. Reject ambiguity explicitly. Do not accept a location derived by fitting the known resources.

3. **Generic conditional predictor.** Build a research-facing wrapper around the existing unchanged geometry/selection code, not a new fitted generator. For each supported source and candidate context, output provenance-bound source identity, admitted mask/weight-vector alternatives, ordered native geometry and boundary intersections where supported. Separate ordinary veins from Special helium-3, terrestrial/rarity-6 Water and atmospheric admission. Classify per-result: invariant, conditional alternatives, unsupported/unknown; for presence: modeled across all alternatives, modeled in some, modeled in none *within the qualified complete scope*, or unknown. Unmodeled must never be called absent. For variable sources never select an alternative by the beacon location unless the native rule actually justifies it. Include a human-readable summary and deterministic machine-readable output.

4. **Ground-truth acquisition and revelation design.** Identify exact feasible observation APIs: Workshop's actual ordinary resource-admission/transfer (for presence), and source-associated native accepted-region geometry (for geometry). Saved equipment and extractor-catalogue screenshots are positive-only or weaker controls, not exhaustive negative or exact geometry oracles. X-Tech operation is not ordinary-resource proof. Build the generic reducer/adapter around qualified prior native observation contracts and exercise with existing captured controls/disposable synthetic fixtures. If universal live acquisition is not currently qualified, do not claim it is ready: state the smallest missing instrument/callback/context, and return a specific Stage B prerequisite. No new live observer or placement harness unless independently justified and within offline authority.

5. **Precommitted freeze and reveal gate.** Define immutable, hash-identified tool source, dependencies, installed inputs, corpus, schemas, selection/eligibility policy, coordinate transforms, prediction output, alternative set, comparison rules and ground-truth collector procedure. A freeze record must bind exact bytes and timestamps and identify allowed participants. The observation side may reveal resource data only after an independent gate validates the prediction package and its freeze. Prevent backdated or revised prediction overwrite. If a tool defect appears after exposure, retain the original prediction and outcome; mark the trial compromised/invalid when justified, then require separate approval for a corrected tool and a genuinely new trial. No unreported post-hoc tuning.

6. **Fixed evaluator/comparator.** Apply pre-frozen rules for complete ordered binary32 point/width/bounds equality, source identity, matched Workshop and session context, area admission versus geometric intersection, per-resource presence, conditional-alternative inclusion, unknowns, and failures to obtain complete ground truth. Report exact contradictions and partial matches, do not collapse all results into pass/fail or a single accuracy number. Distinguish *engineering/protocol compliance* from *scientific correspondence*. A valid negative finding is an accepted experiment outcome; a faulty ground-truth read is an acquisition failure, not a negative result. Include independent oracle/anti-leak checks.

7. **Repeatability without site tailoring.** Support Kreet, Vectera, Jemison under the same frozen logic; if one is outside supported installed-generation scope, report the capability gap *before* test site selection, not after seeing resources. Include a repeat-trial policy, independent trial IDs, no selective exclusion, and evidence that prior trials cannot feed new location-specific tuning into a supposedly frozen tool version. Creation of the actual new outpost must be normal player gameplay in a disposable protected save; the player need not hit a preselected globe pixel or exact beacon offset. Do not require impossible hand placement.

8. **Keep work proportional.** Reuse existing source collectors, archive access and save protection. Prefer a small strict-schema file bridge and CLI to building a framework. No expansion into full terrain procgen, automated beacon placement, comprehensive save serialization, or a new debugger architecture. Record exact technical gaps honestly. Use synthetic and existing historical controls to demonstrate the tooling; never call historical replay a novel prospective validation.

**Negative/insufficiency outcome:** If exact location extraction or ordinary native ground-truth acquisition cannot be qualified with available offline evidence, complete the bounded investigation and return a concrete missing operand, blocker, alternative design, and reviewed Stage B readiness assessment. Do **not** manufacture data or call a partial toolchain trial-ready. Research may legitimately find a method unsuitable, but mandatory engineering deliverables cannot be waived or relabeled PASS. Continue in-scope diagnostics/corrections and qualification before declaring failure. Escalate only a genuinely missing permission or essential external evidence, identifying it precisely; do not seek a new brief for routine test failures.

## Validation and review protocol

Use separate disposable synthetic mock saves and resource-bearing fixtures with controlled inconsistencies; no authentic new experimental site is introduced in Stage A. Test malicious extra fields, extractor/resource data embedded in strings, symlink/junction escape, path traversal, inherited permissions, hidden sidecars, predictor attempts to inspect the custodian area, binary32 precision, Workshop ambiguity, wrong planet, unrecognized frames, incomplete admission and inconsistent identity/epoch. Include a sealed-prediction mismatch that the comparator reports accurately **without making the trial a failure**. Include a correct conditional result with a different winning alternative; neither should cause tool modification. Independently test that source code and registered protocol cannot be changed after the freeze without a new trial identity.

All acceptance criteria must be frozen before execution. Deliver a compact contract (task type, in/out scope, methods, success and negative-result criteria, authority, evidence and escalation), independent reviewer package, literal byte hashes/manifests, complete/task-only diffs, unchanged HEAD/index and a concise final disposition. Stage B run card must identify the player-only fresh outpost creation, protected save custody, exactly who runs the isolation boundary, freeze/reveal event, how truth is obtained, abort conditions and separate explicit maintainer GO. **Do not initiate Stage B, create any experimental outpost, or disclose truth to the prediction role.**

### Governing principle

**The experiment succeeds procedurally when it produces reproducible, independent, honest and comparable scientific evidence—not when our model happens to predict Starfield correctly.** A wrong prediction accompanied by qualified ground truth and an uncompromised blind protocol is an especially valuable, valid result. Do not incentivize the revelator, predictor or reviewer to prefer agreement.
