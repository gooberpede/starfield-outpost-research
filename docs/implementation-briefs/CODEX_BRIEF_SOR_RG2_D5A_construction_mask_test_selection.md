## 3. Research tasks

### T1 — Freeze the candidate source population

Inventory all nonuniform-mask sources currently identified for the three candidate outposts, including available source identity, SFTR/SFPT/SFBK or BIOM context, frames, reference coordinates, owner key, nominal source bounds, first-construction-query provenance, mask sampling and uncertainty. Include all **13** D5 mixed-mask sources if that remains the current inventory; reconcile any changed count explicitly against the original frozen record.

Do not substitute outpost beacon coordinates, later source-cell queries, or saved extractor positions for the original constructor query. If the historical query is unavailable, label it `UNKNOWN`.

### T2 — Determine genuinely discriminating alternatives

For each source, enumerate the **independently supported** possible initial mask states/queries, noting which are native-established, installed-data-derived, conditional or unknown. With unchanged generation math and installed settings, calculate bounded **conditional outcomes** for each distinguishable state:

- resource candidate identity and ordering;
- chance selection and source path effects where support permits;
- ordinary vein-resource availability inside the relevant outpost footprint;
- differences among plausible masks and the expected native observation that separates them.

Do **not** invent a continuous parameter search or choose masks by matching saved extractors or screenshot catalogue entries. Avoid equating an absence from a saved extractor set with absence of a vein. Keep unrelated Water admission and Special/atmospheric mechanisms separately classified.

Define a compact per-source discrimination matrix: possible source contexts, supported mask candidates, differing predicted resources/paths, specific unknown operand, and what each possible captured mask/result would falsify. Record cases that are *not* discriminating rather than manufacturing a contrast.

### T3 — Evaluate acquisition feasibility and rank the sources

For every candidate source evaluate:

1. **Hypothesis discrimination:** Does one real source-construction-query observation separate meaningful predictions, preferably for a currently indeterminate association?
2. **Identity binding:** Can an observation be joined to the exact source/Workshop rather than body or nearby geometry alone?
3. **Natural event likelihood:** Is ordinary save load/travel/build-mode interaction likely to trigger source creation versus cache reuse? No invented probability or promised trigger.
4. **Controls:** Available matching native geometry or independent saved/gameplay evidence, and what it can and cannot establish.
5. **Operational complexity:** Number of required stop sites, phase switching, receipt size/completeness and repaired debugger teardown path.
6. **Historical confounding:** Whether unusual VIII-b lifecycle history might cloud interpretation of canonical generation.

Choose **one primary source** and at least one justified alternative. If evidence is insufficient to rank decisively, make the selection conditional on an objective, offline-checkable prerequisite rather than arbitrary intuition. Explain explicitly whether VIII-b is chosen or deferred and why. This is a **canonical-generation** decision; do not launch a historical instability investigation.

### T4 — Produce one scientifically targeted proposed live run card

Prepare a complete **unexecuted** run card targeting the chosen source, with an exact discriminator and event association; do not merely stop on the first same-planet generator invocation. Require a new observation of the construction query and sampled mask **positively bound to the selected source**. Do not assert a newly generated source necessarily represents the historical Save52 source epoch.

The run card should state:

- exact executable/installed-definition and collector identity guards, source/Workshop keys and expected native stop sites from verified prior mappings;
- required acquisition fields, source and thread lifetimes, query/frame transformations, mask operands and branch/selection evidence;
- useful scientific **GO/STOP** conditions and explicit partial/no-hit/invalid categories;
- natural gameplay sequence, no forced cache invalidation/regeneration and no automatic second session;
- preflight/postflight protected-save and independent-backup hash checks per `SAVE_PROTECTION.md`; active ordinary autosaves/exitsaves remain diagnostic-only, while designated/manual/quicksaves and archived backups are strictly protected;
- Steam/Cloud checks, durable receipt acknowledgement, recovered raw evidence and acceptable disposable-process termination;
- whether the existing collector suffices, or exactly what **offline implementation and synthetic qualification** is required before a retail pilot could be approved.

A design-only collector proposal must never be labelled retail-ready. If implementation is necessary, recommend a bounded engineering continuation; no need to implement a large new observer during this **selection** assignment. An independent reviewer must assess the run card's *information gain under its normal successful outcome*, not only syntactic completeness or likelihood of a breakpoint hit.

### T5 — Preserve validation independence and future stability work

Freeze any conditional predictions **before** comparing them to screenshots/saved witnesses. Do not change D2/D3/D4E/D5 frozen results or the shared generator to force a preferred experimental case. Verify all **ten** exact native geometry controls remain unchanged for any analytical-code change that could affect them. Preserve the original VII​I-b eyewitness account and D1 uncertainties as a separate potential later experiment; do not assume a bug or use abnormal historical behavior to infer canonical rules.
