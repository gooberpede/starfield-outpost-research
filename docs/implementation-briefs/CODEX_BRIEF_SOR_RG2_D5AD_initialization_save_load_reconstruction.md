Distinguish **compiled possible paths**, **actual observed B1/B2 events**, **executed controlled evidence**, and **unknown historical operations**. A plausible ordering is not a measured Save52 ordering.

- **D5AD-Q1 / GC-02 — Data provenance and readiness.** Establish how resource definitions (including relevant IRES/resource dictionaries), geographic sources/Grids, raster data, descriptor/BIOM/component inputs, and any necessary supporting indices are obtained, initialized, cached, and made available to native generation. Identify ordering constraints, parallel branches and actual B1/B2 boundaries. Determine which operations are necessarily before or after the save-load checkpoint, and which cannot be placed from existing runtime evidence. **Completion:** a coherent chronology supported at every claimed edge; don't substitute a list of possible callbacks for a demonstrated specific-load chronology.
- **D5AD-Q3 / GC-05 — Saved versus reconstructed state.** Classify the full relevant resource-generation state: directly serialized/restored, regenerated from saved/static inputs, process-transient, conditionally retained, or unresolved. Follow native save readers/writers where material and corroborate using **read-only copies** of the protected Save52 when needed. - **D5AD-Q4 — Handoff to fast travel.** State exactly which resource-generation inputs and runtime structures are established, absent or contingent by the time the player is in the Lodge after Save52 loading, and how subsequent destination preparation can use or change them. Distinguish a Jemison-linked interior-exterior preparation *possibility* from an observed actual Lodge request. Identify any state the B2 target's first observed demand necessarily inherited. **Completion:** an integrated, falsifiable state-transition model joining Q1–Q3 to later demands, not independent subsystem narratives.
