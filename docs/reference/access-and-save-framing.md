## Frame the sample before interpreting a field

1. **Pin source and domain.** Hash the named input and record format/version,
   directory and transform. Physical original offsets, decoded logical-stream
   offsets and record-relative positions are different domains. Native static
   VA minus preferred image base gives an RVA. A relocated runtime VA uses
   the actual module base plus that RVA. Neither is a file or save offset.
2. **Bound the record.** On the supported R3 grammar, header flags control
   optional record type and little-endian change flags, tagged counts and
   length. The logical record separates three-byte reference tokens, two-byte
   string indices and body bytes. Check declared count and exact directory
   closure. Unsupported count tags and header bits stop the qualified parser.
   An omitted type can require inherited engine context.
3. **Resolve identity and interpret only the supported branch.** The
   three-byte big-endian tagged RefID uses save context and remapping. Base
   FormID, reference identity, saved string index and resolved runtime handle
   have separate roles. A current pointer belongs to one process and object
   lifetime. A qualified inline initial-data type 5 beacon is one path.
   Alternate initial-data branches, inherited types, default/leveled content
   and unsupported extra tails constrain what can be recovered.
4. **Follow the loader and consumer.** A valid owner edge, Health modifier,
   item row or timer scalar gives an input to reconstruction. Current
   ownership, equipment, crew perk buckets, allocation or displayed
   summaries depend on the supported writer/reader and current context.
   Failed resolution, an opaque branch and positive empty inventory are
   different outcomes.
