# RC1: capability and access matrix

[Answer](report.md), [60-question map](../../audits/README.md#archive-lookup) (`audits.zip :: docs/audits/outpost-rc1-2026-10/gap-reconciliation.md`),
[exact Papyrus declarations P01–P22](papyrus-interfaces.md), [pins](sources.md).
Each row is a bounded action, rather than a subsystem-wide extensibility claim.
The three avenues overlap. Definition authoring and mutation of a running operand
are distinguished; no custom record, script or mod was built or loaded here.

Evidence labels are independent per route: **STATICALLY ESTABLISHED** (SE) means
an installed declaration or an existing concrete data/consumer chain;
**DEMONSTRATED** (D) means actual observed use for the specified claim;
**PROVISIONAL** (P) is a grounded but incomplete route association;
**NOT ESTABLISHED** (NE) means the named checked surface provides no supported
interface. **Not investigated** (NI) records no route search, not an absence.
There are no new D runtime claims. Source SAVE demonstrations remain identified
in the final column and do not validate an authored extension. A P-ID link means
the exact declaration in the companion document, not a guessed API name.

FormIDs below are file-relative Starfield.esm unless an add-on is named. They
are not save tokens, handles or runtime pointers. Native addresses are preferred
static hexadecimal VAs on the pinned EXE, image base `0x140000000`; other builds
are untested. Native consumers are OBSERVED-INTERNAL, never automatically safe
integration points. SE does not mean VALIDATED-INTEGRATION.

These rows establish existing access surfaces, including useful scoped negative
results. Authoring a new behavior outside an inspected protocol, extending a
record population and invoking an existing call are different capabilities.
The audit proposes no method to implement an absent interface. Safe external
invocation, arbitrary override conflicts, loaded lifecycle coherence and complete
event coverage remain unqualified unless a cited source says otherwise.
