# Access and save framing

Start with the fact you need. Use definitions for what a recipe, device or
perk configures. Use a qualified saved record for what the snapshot carries.
Use the relevant native consumer or a controlled observation to investigate
what the running game actually resolves and uses. A menu can show a cached
summary of only part of that state.

## Where the information lives

| Channel | Useful question | Example |
| --- | --- | --- |
| ESM records and Creation Kit authoring | What does an installed recipe, keyword, global, perk or actor-value default supply? | A recipe points to a shared quota global. Construction reads a current threshold and a current set of representatives. |
| Papyrus declarations and shipped compiled scripts | What operation or event is exposed, and what does an installed caller actually do? | AssignCrew is declared. Ordinary robot placement uses it with a different admission path from the Crew menu. |
| Serialized snapshot | Which supported records, identities, relationships and values are stored? | A display slot can identify a world item even when the fixture has zero saved inventory rows. |
| Native runtime and UI | What does a specific consumer resolve, evaluate, update or display? | The Locations Crew badge copies list length. A perk consumer resolves actors and tests their current entries. |
| Research instruments | What did the stated sample, trace or derived calculation capture? | A static path explains a conditional effect. A controlled observation needs its own matching build, inputs and acquisition coverage. |

## Reconstruct a saved fact

First establish the source and version. Read the correct container and logical
stream, then use directory and record boundaries to separate the body from
reference and string queues. Resolve saved tokens through that save's
tables and plugin context. Only interpret a branch whose layout and owning
record are supported. A placed reference can point to an installed base
definition and carry instance extras. After load, current handles and
derived structures are rebuilt under the loader's own conditions.
[Offline save analysis](../../save-analysis/README.md) ·
[Identity](identity.md)

For example, a quest record can mention the beacon base in its reference
queue. Counting that occurrence as a constructed outpost would confuse a
queued reference with the record's identity. An exact framing check can pass
while inherited types, alternate bases or opaque extras still prevent an
exhaustive outpost census.
[Framing and counterexamples](../experiments/active-outpost-identification.md#competing-rules-predictions-and-falsification)

## Judge what an interface supports

The capability audit identifies definition routes, declared Papyrus routes
and configuration operands for particular actions on the studied build.
Some have installed call sites or sampled saved counterparts. A generic
linked-reference operation can change a keyed relationship. The ordinary
output-link transaction also depends on admission, native registration and
refresh. Safe use of the primitive as a replacement for that transaction
remains unvalidated. Likewise, a serializer explains how the engine writes a
record. It supplies no validated save editing procedure.
