All working receipts and D: leases live under ignored
`.local-work/resources-evidence-consolidation/`; archives/index versions live under
`.local-work/research-archives/`. Synthetic source fixtures also use the existing
Stage B workspace. Both C: and D: must retain 40,000,000,000 available bytes;
material writes reserve capacity on the actual destination volume. C: staging
is restricted to fresh leases below
`C:/Users/User/Downloads/sor-resources-evidence-staging`; it holds no archive
replica and is cleaned only after proof. Independent alternate payload proof and
a stopped writer are prerequisites for sealing an interrupted working subset.

Original acquisition and historical admission scripts remain closed methods.
Restoration does not authorize running them, bypassing old identity checks or
changing a scientific predictor. Only the existing historical corpus reader is
replayed, through its unchanged isolation driver and restored historical modules.

The transaction reuses Cargo's wire schemas and same-handle NTFS disposition.
Its explicit resources profile adds protected exclusions and bounds simultaneously
open source handles. Approved implementation and Git identity files stay locked;
approval is revalidated after acquiring those locks. Source identity is checked
before a new INTENT and again before disposition. The archive, index and controls
remain locked through the transaction. Journals validate each transition once
and fully authenticate their chain on reopening. Routine verification still reads
control/baseline/journal metadata in addition to reported payload objects.

The tracked `selection-proposal.json` is a reviewed trust root, never an activation
instruction. It pins the complete local control/profile closure and future active
selection bytes. Mutable local receipts cannot refresh those expectations. The
old Cargo index remains an immutable compatibility version for its committed
baseline; the combined proposed index becomes the central current version only
after the separate GO. It introduces one additional owning archive, rather than
per-experiment archives or duplicate scientific payload ownership.

Retain a failed partial and all diagnostics. Inspect its authenticated controls;
never infer completion from a directory name. A fresh restore can retry from the
complete verified archive with a new partial directory. Cleanup uses the existing
authenticated exact lease cleanup after scientific/review proof, with no recursive
fallback. Unknown outputs, source changes or ambiguous journals stop the affected
operation. Source deletion has no automatic rollback; verified restoration and
an explicit recovery decision are required after an unresolved interruption.
