## Owned helper lineage and effects

All acquisition helpers are retained under `.local-work/l3-*.py`, their exact
hashes in sources.csv. Existing owned L1/L2 E2ReadSession/Cr1Recon/TransitCalls,
Workshop membership/population, CR1 extra reader, record framing and streaming
decoder methods are reused/adapted under SOR-P-0002. This is maintainer-owned
reuse, not an unreviewed external implementation. No decompiled game text is
copied into authored tools.

- l3-intake.py reads exact named source saves, existing L2 protection pins,
  screenshots, installed game/analysis inputs and Git identity. It copies six
  originals and eleven named witnesses to new ignored protected storage, hashes
  them and sets copies' read-only attribute; originals are never written. It
  starts an owned hidden JVM worker with readOnly/noanalysis and local settings,
  cache and logs. The first attempt selected all 23 JPEGs and failed its 11-image
  assertion before decoding or worker startup; corrected selection verifies and
  reuses existing copies. Twelve ancillary older screenshot copies remain local,
  outside the 11-witness ledger, excluded and not destroyed. They are not newly
  claimed L3 witnesses. Read-only attributes and hashes are not hardware WORM.
- l3-saves.py reads/decompresses protected copies through the existing decoder
  with elapsed policy disabled, independent arithmetic framing walk, owned root,
  prefix and counted-extra readers. It writes six exclusive local JSON scans.
  l3-compare.py writes four ID/body/queue/flag comparisons and the full positive
  bulldozed-channel rows; it does not classify their meshes. Decoder scratch is
  temporary; neither helper loads Starfield.
- l3-defs.py/l3-detail.py read the physical installed ESM through owned
  esm_records and selected development PSC members in existing
  ContentResources.zip; they write fresh local field/offset/hash receipts. No
  script was executed and development PSC is not a claimed installed PEX oracle.
- l3-pe.py reads installed PE sections, strings, constants and vtable qwords;
  l3-read.py requests existing native functions/xrefs or displays local exports.
  l3-addscan.py adds a bounded existing-instruction literal inventory to the
  **local reader source**, never to the Ghidra program. The source change is
  hashed; no symbols/types/comments are changed.
- E2ReadSession.java reads numbered requests and writes exclusive local native
  exports. Function listings are capped at 600 instructions; the selected full
  decompilation cap of 250,000 characters and tool timeout of 30 seconds are
  reported limits, not semantic coverage.
  The literal inventory is a discovery aid, not a typed field/absence proof.
  l3-restart.py preserves failed request 025 and its logs after a window centre was not
  an existing instruction, explicitly marks that request FAILED, and starts the
  same read-only reader for later requests. No incomplete request is a PASS.
  The final owned worker exits through its stop sentinel. All persistent input
  hashes are checked after exit.
- l3-ledgers.py derives concise authored numeric/hash CSVs from sealed receipts;
  its first syntax error occurred before writing them. l3-summary.py only prints
  selected existing scans. l3-indexes.py edits only intended documentation.
  l3-package-setup.py adapts the owned L2 exporter for L3, retaining byte-exact
  forward/reverse tests in fresh .local-work/review-patches trees, real-tree reverse checks,
  untracked-text coverage and unchanged-brief handling. No staging/application
  to the working tree or network operations.

The verifier checks primary byte correspondence, source identity and represented
controls. It does not simulate physics, reconstruct missing generated geometry,
prove screenshot reference identity or replace independent semantic review.
Native/definition/save/screenshot bulk payloads stay ignored LOCAL-ONLY;
authored analysis and source metadata remain REVIEW-REQUIRED.
